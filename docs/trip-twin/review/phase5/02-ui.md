# Phase 5 · 02 — UI / visual hierarchy review (side panels)

Reviewer: UI. Review only, no code changed. Screenshots are in `phase5/shots/`. `1600-NN` is the default reference; `1280-NN` is cited where the narrower width breaks something.
Every colour below is an existing token in `tripTwin.css :root`, or a new token defined here with its hex value and contrast. Contrast figures are measured against `--tt-card #07212c`.

**Problem in one line:** a choice, a selected choice, a primary action and a secondary action all use the same 32px grey outline box (`.tt-btn` / `.tt-tb` / `.tt-route-seg .tt-tb`). The selected fill (`rgba(42,74,89,.9)` ≈ `#274654`) is only **1.66:1** against the card. So the user can't tell what is a choice, what has been chosen, or what will make something happen.

## B. Findings

### P0-1 · Path section has no order, no labels and no visible outcome
**Shots:** 1600-02, 03, 05; 1280-04.
**Problem:** Destinations, modes and "Plan your own path" are one cloud of identical outline buttons. Walk and Drive secretly act as the "go" button. "To Fairmont Austin" is pre-selected in 02, but you can barely see it. The instruction sits *below* the controls in 11px dim text ("Pick where from, then Walk or Drive…").
**Spec (path-section anatomy, `.tt-route`):**

```
PATH FROM THIS PERSON                         ← section kicker (C §section)
[1] To                                        ← .tt-step
   ( ) Fairmont Austin
   (●) Nearest hospital                       ← .tt-choice, selected
   ( ) Nearest rally point          [Draft]   ← dashed tag, 11px --tt-text-dim
[2] How
   [ ✓ <walk-svg> Walk | <car-svg> Drive ]    ← .tt-seg2
[ Show walking path            → ]            ← .tt-btn.primary.block
or  Plan your own path                        ← "or" 11px dim + .tt-link
```

- `.tt-step`: grid `20px 1fr`, gap 8, margin `12px 0 6px` (the first step uses 8px top). The number is an 18px circle with a 1px `--tt-edge-ctl` border, mono 11px weight 600 `--tt-text-2`, centred. The label is 12px/16px weight 600 `--tt-text`, sentence case: **"To"** on traveler cards, **"From"** on place cards, **"How"** for mode. The label is the radiogroup's `aria-labelledby`.
- Choice rows and segmented control use the role specs in A. Indent them 28px so they line up with the step label text.
- Rewrite the labels: drop the repeated "To "/"From " prefix (the step label carries it). Move "(draft)" into a dashed tag. **No information is lost.**
- Glyphs are 14×14 inline SVG, `stroke: currentColor`, 1.5px: a walking figure and a car side view. Don't use emoji; they render in colour and break the palette.
- Walk is pre-selected (school-group default), so the primary button is live as soon as there is a destination. *(Behaviour change; flagged to UX.)*
- The primary label follows the mode: "Show walking path" or "Show driving path". Loading: "Finding path…" with `aria-busy`. Disabled (no destination): "Pick a destination first".
- Section spacing: `margin-top: 16px; padding-top: 12px; border-top: 1px solid var(--tt-border)`.

### P0-2 · The selected state is invisible (G17 override)
**Shots:** 1600-03 ("To nearest hospital" picked), 1600-04 (Walk).
**Problem:** The G17 rule at `tripTwin.css:1765` changed `.tt-route-seg .tt-tb.on` to a `#274654` fill (1.66:1 against the card) with a 2px inset underline. The unselected border `#4a6b78` is only **2.9:1** (fails 1.4.11). The earlier white-fill rule at line 1464 is dead code.
**Spec:** Delete both `.tt-route-seg .tt-tb.on` blocks and the `#4a6b78` override. Use `.tt-choice[aria-checked=true]` and `.tt-seg2 [aria-pressed=true]` from A. Selected = tint + `--tt-text` 1px border + weight 600 + ✓ or ● glyph. Never use fill alone.

### P0-3 · No primary action, so the user doesn't know what makes the path appear
**Shots:** 1600-02, 05, 14.
**Problem:** Nothing on the card looks like "do it". Users click a destination, see nothing happen, and stop.
**Spec:** Add the step-3 primary from P0-1 (`.tt-btn.primary.block`, 36px, full width, `margin-top: 12px`). When a path is shown, the button is **replaced** by the result block (P1-5), and any later To or How change re-runs the route automatically, as it does today. In the editor (14), Walk/Drive stays a segmented control with no primary, because the router re-runs on change. "Save path" is that panel's single primary.

### P0-4 · Layers/Display popovers: legends read as rows, no header, no close, no outside-click dismiss
**Shots:** 1600-07, 1600-08, 1280-07.
**Problem:** The title "LAYERS" uses the same kicker style as the group heads "PEOPLE" and "HAZARDS". Legend lines (11px, 22px indent, swatch) sit at nearly the same weight and rhythm as toggle rows. Notes ("Saved by an operator · long dash · Advance shows the selected day") wrap like rows. Locked rows ("always on") show a greyed checked box, which reads as broken. Checkboxes use `accent-color: --tt-edge-ctl`, so a checked box looks disabled. No ×, no outside-click close (`closePops` only runs on Esc and on item clicks; there is no document `pointerdown` handler). In Display, the **MOTION** kicker sits flush against the relief note (0px gap).
**Spec:**
- **Header** `.tt-pop-head`: sticky top, 40px, flex space-between, `margin: -12px -14px 8px; padding: 0 8px 0 14px`, background `--tt-card`, border-bottom 1px `--tt-border`. Title in **sentence case**, 13px/18px weight 600 `--tt-text` ("Layers", "Display"), followed by a `.kbd` hint ("L" / "D"). `.tt-x` close (28×28) on the right.
- **Group header**: keep the kicker (mono 11px, 0.12em, `--tt-text-dim`). `margin: 16px 0 4px`, 1px `--tt-border` divider above. The first group has no divider.
- **Toggle row** `.tt-layer-row`: min-height **32px**, padding `0 6px`, radius 3, 13px/18px weight 500 `--tt-text`, hover `--tt-hover-bg`. The whole row is the label. Checkbox 16×16 with `accent-color: var(--tt-text)`, so checked reads as on.
- **Locked row**: replace the disabled checkbox with a 16px lock glyph (`--tt-text-dim`). Label stays `--tt-text`. Right-aligned "Always on", 11px `--tt-text-dim`, sentence case.
- **Legend** `.tt-key`: **not a row**. `margin: -2px 0 8px 30px` (aligns under the label text: 6 + 16 + 8). A `border-left: 1px solid var(--tt-border); padding-left: 8px` tree line ties it to its toggle. 11px/16px `--tt-text-dim`, `gap: 2px 12px`. Swatch 16px wide, 2px high. No hover and no pointer cursor.
- **Note** (explanatory sentence, e.g. "Advance shows the selected day", "Turn them on or off in Layers › Site"): `.tt-pop-note`, 11px/15px `--tt-text-dim`, same 30px indent, placed *after* the legend, max 2 lines.
- **Disclosure row** (Weather ▸, Saved paths ▸): 28px, 12px weight 600 `--tt-text-2`, chevron 10px in a 16px column so it aligns with the checkboxes. Expanded children indent to 30px.
- **Display**: groups "Grid & elevation" and "Motion" each get the group-header spec (16px gap + divider). Select rows 32px, select 32px high and 160px wide. "Keyboard shortcuts" moves to a footer row with a top divider.
- **Dismiss** *(behaviour, for dev)*: a `pointerdown` on `document` that lands outside the open `.tt-pop` and outside its trigger closes it. Don't `preventDefault`, so a map drag still rotates the camera. Opening another popover's trigger switches popovers. Esc closes and returns focus to the trigger.
- Width 340 → **360px**.

### P1-5 · Path result block is a three-line bold blue sentence
**Shots:** 1600-04, 1280-04.
**Problem:** "Walk from Emi Sato (position 1m old) to Ascension Dell Seton Medical Center at The University of Texas · 1.8 km · walk 28–37 min (group pace)" is one 12px/600 blue run. The numbers that matter are buried at the end.
**Spec** `.tt-path-card`. `routeCards()` should return `{kicker, metric, route, lines}` instead of one `title` string.
- Container: background `--tt-path-tint`, `border-left: 3px solid var(--tt-path)`, radius `0 3px 3px 0`, padding `10px 12px`, `margin-top: 12px`.
- Kicker: "SUGGESTED WALKING PATH" (or "ALTERNATE"), mono 11px 0.12em `--tt-path-text`.
- Metric: "1.8 km · 28–37 min", mono 16px/20px weight 600 `--tt-text`, followed by " group pace" in 11px `--tt-text-dim`.
- Route: "Emi Sato (position 1m old) → Ascension Dell Seton…", 12px/17px `--tt-text-2`, `margin-top: 2px`.
- Caveats: one line each, 11px/15px `--tt-text-dim`, `margin-top: 6px`. The rain-pace and avoid-area lines keep their wording.
- Flagged: border `--tt-attention`, background `--tt-attn-tint`, kicker colour `--tt-attention`, and a ⚠ glyph before the flag line. Never red.

## C. Keep (do not change)
- The dark navy/teal glass surfaces, 1px `--tt-border` frames and 4px radius. They are calm and on-brand.
- Mono kickers with 0.12em tracking for section labels, and mono tabular numbers for counts and metrics.
- The colour discipline: green outline chips for approved places only, dashed borders for drafts, blue only for paths, amber left bars and counts for attention, and red only for the incident border and pills. The new roles stay inside it.
