## P0

### P0-1 · The path section has no order and no labels (traveler and place cards)
**Refs:** 1600-02, -03, -04, -05; 1280-02, -05.
**Problem.**
- The card shows three rows of identical outlined buttons: destinations, then Walk/Drive, then "Plan your own path". Nothing tells the user that rows 1 and 2 are two separate questions, or that row 3 is a different path entirely.
- The destination is silently preselected (`drawRouteSection` sets `originKey` to the first enabled option), so "To Fairmont Austin" looks chosen before the user has done anything (02).
- Clicking "To nearest hospital" (03) only moves a faint highlight. The real trigger is Walk/Drive, which has no label saying so.
- The hint is wrong on the traveler card. It says "Pick where from", but on a traveler card the user picks where *to*.
- "Plan your own path" has three different looks: an outlined button when idle, an underlined link once a path shows (04), and a button again in Advance.

**Decision: show the path automatically, with no "Show path" button.** "How" is preselected (Walk, remembered for the session). The destination or start is never preselected. One click on a destination or start draws the suggested path.
Why:
- (a) Every click then has a visible result. State 03, where nothing changes, can no longer happen.
- (b) A hospital run is one click from an open card, which matters under time pressure.
- (c) Fetching is cheap and easy to undo (Esc / Remove path), and the result is always labelled "Suggested · unverified", so an accidental fetch commits nothing.
- (d) A third button would compete with "Plan your own path" for the primary slot.
- Why the endpoint is never preselected: it is the meaningful decision (from the hotel or from the person?), and a silent default reads as a choice the user made.

**Spec: one component (`renderRouteSection`) used on both card types**
```
PATH FROM EMI SATO            ← kicker (existing title; place card: "PATH TO <SHORT NAME>")
(1) Where to                  ← step label; place card: "(1) Where from"
  ( ) Fairmont Austin · group hotel
  (•) Nearest hospital · Ascension Dell Seton…        ← vertical radio rows, full width
  ( ) Nearest rally point · draft, not approved
(2) How
  [ Walk ✓ | Drive ]          ← two joined segments
(3) Suggested path
  idle:    "Choose where to in step 1 to see a suggested path."   (tt-note)
  loading: "Finding a suggested path…"   (keep any path already drawn, at 50% opacity, until the new one arrives)
  ready:   existing path card(s) (blue left rule) +
           [ Edit or save this path ]  (tt-btn primary)    Frame path · Remove path (Esc)   (tt-link)
  error:   existing error copy + straight-line distance
──────── or ────────          ← 1px --tt-border rule with a centred "or" in --tt-text-dim
[ ✎ Plan your own path ]      ← tt-btn ghost, full width, always shown, same style in every state and in Advance
```

- **Step labels.**
  - Type: 12px/16px, weight 600, `--tt-text-2`.
  - The number sits in a 16px circle: 1px `--tt-edge-ctl` border, digits in `--tt-mono` 11px `--tt-text-dim`.
  - Spacing: `--tt-step-gap` above each step, 6px below the label.
  - Use `<h4>`-level semantics, or put the text in the group's `aria-labelledby`.
- **Option text.** Drop the "To"/"From" prefix, because the step label carries it.
  - Traveler card: "Fairmont Austin · group hotel" / "Nearest hospital · {name}" / "Nearest rally point · draft, not approved".
  - Place card: "Fairmont Austin · group hotel" / "{Person} · selected person · position {age} old" / "Group centre · {n} people".
  - Optional dim meta on the right: the straight-line distance, when known.
- **Disabled options stay visible.** Put the reason inline in `--tt-text-dim` (for example "Selected person · select someone on the map or in the list first"), not only in a `title` tooltip.
- **Changing an answer while a path is shown** fetches again straight away. This already works for the origin; do the same for the mode.
- **Camera.** On the *first* show only, frame the path if its bounding box is not fully on screen. Respect Reduce motion: frame without animating.
- **Copy.** Change "Asking OpenStreetMap routing…" to "Finding a suggested path…". Change "Clear path (Esc)" to "Remove path (Esc)" (see P1-12).
- **"Edit or save this path".** Calls the existing `onEdit`. The path editor opens with the same endpoints and mode.

### P0-2 · Selected state is close to invisible, and the choice controls are plain buttons
**Refs:** 1600-03 vs -02 ("To nearest hospital" vs "To Fairmont Austin"), 1600-04 (Walk).
**Problem.**
- The "G17" override at `tripTwin.css:1765` turns `.on` into a faint fill plus a 2px inset underline. At a glance it cannot be told apart from hover.
- The unselected border `#4a6b78` measures about 2.9:1 against `--tt-card`, which is below the WCAG 1.4.11 minimum of 3:1.
- The ARIA is `aria-pressed` on buttons inside `role="group"`. That announces separate toggle buttons, not "pick one of three".

**Fix spec (component `tt-choice`, also used by the path editor and Advance):**

| State | Background | Border | Text | Marker |
|---|---|---|---|---|
| Default | transparent | 1px `--tt-edge-ctl` (5.3:1) | `--tt-text-2` 13px/500 | ○ in `--tt-text-dim` |
| Hover | `--tt-muted` @ 60% | `--tt-edge-ctl` | `--tt-text` | ○ |
| Selected | `--tt-muted` (8.7:1 with `--tt-text`) | 1px `--tt-text` | `--tt-text` 600 | ● plus a "✓" suffix on the Walk/Drive segment |
| Focus | (as current) | 2px `--tt-focus` outline, 2px offset | — | — |
| Disabled | transparent | 1px `--tt-border` | `--tt-text-dim`, with the inline reason | ○ |

- **Row height** is `--tt-opt-h` (32px), the full width of the card.
- **Not white fill.** Selected must not use solid white. White fill stays reserved for `tt-btn primary`, so a choice never looks like the action.
- **ARIA.**
  - Container: `role="radiogroup"` with `aria-labelledby` pointing at the step label.
  - Each option: `role="radio"`, `aria-checked`, with a roving `tabindex`.
  - Arrow keys move the selection inside the group. The group's `keydown` handler calls `stopPropagation`, so the global ↑/↓ floor-stepping and the other shortcuts are not triggered while focus is inside it.
  - Do not bind the digits 1/2/3 here. They already switch the scale presets.
- **Delete the G17 override** at `tripTwin.css:1765–1774`, and replace both `.tt-route-seg` blocks with this component.

### P0-3 · Popovers do not close when the user clicks elsewhere
**Refs:** 1600-07, -08, -09, -10. Code: `page.js` 121–148. There is no outside-click or focus-out handling, and Esc never returns focus.
**Fix spec (covers every entry in `POPS`: Layers, Display, Report, Prototype, Help, Sites):**

1. **Pointer outside.** Use one `pointerdown` listener on `document` in the capture phase. If a popover is open and the target is neither inside it nor its trigger button, close it. If the trigger itself is clicked, it toggles, as today.
2. **Map canvas: close only.** If the pointerdown lands on the Cesium canvas, close the popover and swallow the *pick*. Set a one-shot `suppressNextPick` that the selection handler checks, so the selection, the card and any drawn path stay as they are.
   - Drag-to-orbit and wheel zoom still work. Wheel and hover never close a popover.
   - Rationale: the user was dismissing the popover, not choosing a building. A stray pick that swaps the card or removes a path costs more than one extra click.
3. **Other HUD controls: close and act.** This covers rail rows, card buttons, toolbar buttons and chips. These are targeted controls, so one click should do both. Clicking a different popover's trigger switches to that popover (this already works).
4. **Report form (Add reported floor).** If the floor field has a value, an outside click does *not* close the form. Show "Unsaved floor · press Esc or Cancel to discard" in `--tt-attention` under the field. An empty form closes normally.
5. **Focus leaving.** When focus leaves a popover (`focusout` to an element outside both the popover and its trigger), close it without moving focus. This applies to Tab and Shift+Tab.
6. **Esc ladder unchanged** (popover first). After closing with Esc, return focus to the trigger. After closing by pointer, leave focus where the pointer put it.
7. **Not covered:** the path editor (it is a mode, closed with Esc / Discard) and selection cards (closed with Esc / ×).

- **All information:** every count, age, caveat, source line, "Suggested · unverified", "not an all-clear" and "of 27 loaded". This pass only re-orders and labels.
- **Keyboard:** every shortcut (`/`, 1/2/3, L, D, G, E, H, S, V, R, F/Z, `,` `.`, N, ↑/↓ floors, ?, `` ` ``) and the Esc ladder order (popover → advance path → drawn path → place → floor return → selection).
- **Colour rules:** green only on approved places; no red or green on people; blue only for paths (including the new path-line rule in the rail); amber for attention and avoid. The hazard pink stays only on reported incidents.
- **Vocabulary:** the roster bucket words, "group zone", the floor wording and "Reported · not verified" are as specified in 06 §3.
- **Panel positions:** rail on the left, cards on the right, toolbar at bottom centre, top chips. The fixed rail header, with Needs attention scrolling under it.
- **Behaviour:** the path editor's mode banner and its key hints; "Copy for responders" and "Copy floor for hotel desk" as the only primaries in their panels; the Prototype drawer labelled "not operator controls".
