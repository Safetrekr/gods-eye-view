# Phase 5 panel clarity: information architecture review (04-ia)

Reviewer: information architecture. Review only; no code changed.
Inputs: `review/phase5/shots/1600-01…14`, `1280-02`, `1600-text.json`; `06-layer-taxonomy.md` §2, §3.3, §3.7, §3.11, §4.4, §9–§11; `twinHud.js` (`renderRail`, `renderIncident`, `createCard`, `renderRouteSection`), `page.js` (`routeEnds` ~921, `drawRouteSection` ~1012, Advance brief ~1389, `selectSaved` ~1744, Layers ~1924, `weatherGroup` ~2335, `POPS`/`openPop`/`closePops` ~122, keyboard ~2604), `twinData.js:868`, `twinAdvance.js:234`, `twin.html` (Display, Prototype, Help).

Jesse's complaint, restated as IA problems:
1. **Path controls:** destination, travel mode and action look the same and have no labels, so the order of steps can't be seen.
2. **Panels and popovers:** the rail, cards, Layers and Display have no named sections and no visual order.
3. **Closing:** popovers don't close when the user clicks outside them.

Severity: **P0** blocks the task or contradicts itself. **P1** a real findability or vocabulary defect. **P2** polish.

## Findings

### F1 · P0 · Path section: three unlabelled control groups, and a hint that contradicts the buttons
**Ref:** 1600-02, 1600-04, 1280-02; `renderRouteSection` (twinHud.js:980–1059), `routeEnds` (page.js:921).

**Problems**
- The traveler card shows three rows of identical `tt-tb` buttons:
  1. `To Fairmont Austin · To nearest hospital · To nearest rally point (draft)`
  2. `Walk · Drive`
  3. `Plan your own path`
- No row has a label.
- The hint under the buttons says **"Pick where from, then Walk or Drive…"**. On the traveler card the starting point is fixed (the person), and the buttons choose where the path goes *to*. The only written instruction is wrong for this card, because the code shares one hint between both card types.
- `To Fairmont Austin` is already pressed when the card opens (`originKey` defaults to the first end). Step 1 looks done before the user has done anything.
- `Walk` / `Drive` look like a mode setting, but clicking one actually runs the request (`onMode → runRoute`). The mode row is really the "go" button, and nothing says so.

**Spec:** labelled rows that read top to bottom as one sentence. The instruction lives in the row labels, not in a footnote.

```
PATH FROM THIS PERSON                         ← section kicker (fixed end)
To     [Fairmont Austin] [Nearest hospital] [Rally point (primary)]   ← radio group, row label "To"
Show   [Walking path] [Driving path]          ← action buttons (verbs), primary style
       or Plan your own path…                 ← text link, visually third
```
- **Row 1** is a single-select radio group (`role="radiogroup"`, `aria-labelledby` = the row label "To").
  - Keep a default selection, but the row label must make it read as a chosen value.
  - The path is not requested until a Show button is clicked.
- **Row 2** holds the actions. Button text is the result the user gets ("Walking path"), not a bare mode ("Walk").
  - After a path is drawn, the pressed button reads `Walking path · shown`.
  - The other button stays available.
  - Changing row 1 re-runs the request (current behaviour, keep).
- **Row 3** is a link, set apart by "or". It is not a third button of the same weight.
- Delete the footnote hint. The labels replace it.
- After a result, keep the existing order: path card, then actions `Frame path · Clear path (Esc) · Plan your own path`.

### F2 · P0 · One path grammar for every card that offers a path
**Ref:** 1600-02 (person), 1600-05 / 1600-14 (place), 1600-13 (Advance stop), 1600-06 (hotel: no path section at all).

**Problems.** There are four grammars today:
- **Person card:** `PATH FROM THIS PERSON` with `To …` buttons.
- **Place card:** `PATH HERE` with `From …` buttons.
- **Advance stop:** `Go to Long Center` / `Walking path from Fairmont Austin` / `Plan your own path`. These are three unlabelled buttons that mix a camera move with a path.
- **Hotel card:** no path section, even though the hotel is a destination on the person card.

**Spec: one template.** The kicker names the fixed end. The first row's label names the variable end. Rows always appear in the same order: *other end → Show (mode as action) → or plan your own*.

| Card | Kicker (fixed end) | Row 1 label (variable end) | Row 1 options, in this order | Row 2 |
|---|---|---|---|---|
| Traveler / chaperone | `PATH FROM THIS PERSON` | `To` | `{Site}` · `Nearest hospital` · `Rally point (primary)` · `Rally point (secondary) · not approved` (only if present) · `{Hotel}` (at a venue) | `Show` [Walking path] [Driving path] |
| Place (hospital, police, rally point…) | `PATH TO THIS PLACE` | `From` | `{Site}` · `{Name} · last selected` (if any) · `Group center · {n} people` | same |
| Hotel / venue (new, P2) | `PATH TO THIS SITE` | `From` | `{Name} · last selected` · `Group center · {n} people` | same |
| Advance site brief | `PATH TO THIS SITE` | `From` | `{Hotel}` (only option today) | `Show` [Walking path] (Drive when available) |

- Hint text, if any is kept, must come from the card kind ("Choose where to…" or "Choose where from…"). Never share one string.
- In the Advance brief, move the camera action out of the path block (see F13).

### F3 · P1 · Endpoint labels: "(draft)", "nearest", "centre (19)", and a stale person
**Ref:** 1600-02, 1600-05, 1600-14; page.js:960–1010.

**Problems**
- **`To nearest rally point (draft)`:**
  - (a) "(draft)" sits next to "path" and reads as *a draft path*. In 06 §3.6 / Layers, "Draft · not approved" describes the *place*.
  - (b) The code picks the *nearest* rally point by distance, which here is the **secondary, not approved** one (rail 1600-12: `Rally point (secondary) · 390 m N · Draft · not approved`).
  - (c) The rail and the incident panel call the trip's plan `Rally point (primary)`. An operator who clicks the rally option during an incident gets a path to the unapproved point, under a label that doesn't match anything else on screen.
- **`From group centre (19)`:**
  - "centre" is British spelling in a US-English product ("Neighborhood", °F, "US numbering").
  - "(19)" is explained only in a hover title.
- **`From Emi Sato` on the hospital card (1600-05):** Emi is no longer selected. The option comes from `lastPersonId`, so the label claims a selection that isn't visible. In 1600-14 the same slot reads `From selected person` (disabled), a second name for the same thing.

**Spec**
- **Rally options:**
  - Always offer `Rally point (primary)`.
  - Offer the secondary only as `Rally point (secondary) · not approved`.
  - Never use "nearest" for rally points; the trip plan has a primary for a reason.
- **Hospital:** `Nearest hospital`. Its tooltip says "nearest by straight line · not verified" (matches the Advance brief).
- **Group center:** `Group center · 19 people`, tooltip "median of current positions at this site". Disabled state: `Group center · needs 3 current people`.
- **Person end:** `{Name} · last selected`. Disabled state: `A person · select one first`.
- Endpoint names must be the same strings the rail and Layers use for the same objects.

### F4 · P0 · Popover family has no click-outside close and no written rule
**Ref:** 1600-07, -08, -09, -10; `POPS` / `openPop` / `closePops` (page.js:122–147). There is no outside-pointer listener; only Esc and the trigger close them.

**Spec: popover behaviour rule** (name it in 06 as §12.2 *Popover family*).

| Term | Members | Dismiss |
|---|---|---|
| **Popover** (light-dismiss, transient) | Layers, Display, Sites (breadcrumb ▾), Prototype, Keyboard shortcuts (?), Add reported floor | Rules 1–8 below |
| **Panel** (persistent, never light-dismissed) | Left rail, selection card, incident panel, path editor, Advance brief | Close button or Esc unwind only |

Rules:
1. **One popover open at a time.** Opening one closes any other. (Exists; keep.)
2. **The trigger toggles.** Clicking the trigger of an open popover closes it. (Exists.) The trigger shows the pressed style and `aria-expanded="true"` while open.
3. **Click or tap outside closes it.** A `pointerdown` outside both the popover and its trigger closes it.
   - On the **3D scene**, that pointerdown is *swallowed*. It does not also select a pin or building, so closing never changes the selection by accident.
   - On **any other control** (rail row, toolbar button, card), the popover closes and the control acts normally.
4. **Esc closes the open popover first**, before any other Esc unwind step (exists), and focus returns to the trigger (add).
5. **Settings apply immediately.** There is no Apply or Cancel inside Layers, Display or Prototype, so closing can never lose a change.
6. **Exception for forms:** *Add reported floor* closes on outside click only if the floor field is empty. With a typed value it stays open and shows "Not added yet · Show on twin or Cancel". (A typed fire floor is never lost to a stray click.)
7. **Opening or closing a popover never closes a panel** (card, incident panel, editor).
8. **Each popover has a keyboard shortcut that toggles it:** L, D, S, ?, `, R (R only in Live).

### F5 · P1 · A single card template with named sections
**Ref:** 1600-02 (traveler: no section names before PATH), 1600-05 (place), 1600-06 (hotel: FLOORS first, then facts that explain the floor numbering), saved-path card (`selectSaved`, page.js:1744; `kind` = `SAVED PATH · REVIEWED`).

**Problem.** Each card kind was built separately. The only shared section is the kicker. The order of facts, floors, paths and actions differs by kind, so users have to re-learn each card.

**Spec: card template.** Sections appear in this order. A section with no content is omitted. Kickers use the existing `tt-kicker` style.

| # | Section (kicker) | Traveler / chaperone | Place | Hotel / venue | Saved path |
|---|---|---|---|---|---|
| 0 | Identity *(no kicker)* | `TRAVELER` / `CHAPERONE` · name · × | `HOSPITAL` etc. · name · × | `GROUP HOTEL` / `TRIP VENUE · DAY 2 · 19:00` · name · × | `SAVED PATH` · name · × (move review state out of the kicker into section 3) |
| 1 | `NOW` (people) or `DETAILS` (things) | Live · age · ±m / verdict / floor / zone · battery; last line = source (`Sample trip · fictional person`) | bearing and distance from site / address / phone; last line = source | height · `37 floors · US numbering · lobby = 1` (moved up: it is the key to reading Floors) | Day · walk/drive · distance · pace |
| 2 | `FLOORS` | — | — | Floor chart; caption "Select a floor to see who may be on it" | — |
| 3 | `PATH …` (F2) or `CHECKS` | `PATH FROM THIS PERSON` | `PATH TO THIS PLACE` | `PATH TO THIS SITE` (P2) | `CHECKS`: review state (`Not reviewed` / `Reviewed by you · …` / `Review out of date`), avoid-area status, flags |
| 4 | `ACTIONS` | *(inside PATH)* | *(inside PATH)* | — | Edit saved path · Duplicate · Frame path · Mark reviewed |
| 5 | Footer | — | — | — | `Delete saved path`, separated, danger style, last |

Rules:
- The source or provenance line is always the **last line of section 1**, never between sections. (Today's traveler and place cards already do this; make it the rule.)
- Destructive actions are always last.
- A kicker names a section. It never carries an instruction: `FLOORS`, not `FLOORS — SELECT ONE…`.

### F9 · P1 · Layers popover: toggles, keys, notes and locks look alike
**Ref:** 1600-07; page.js:1925–2063.

**Problems**
- Four kinds of row share one typographic level and one indent rhythm:
  - toggles (checkbox + label)
  - keys (swatch + meaning)
  - notes ("Advance shows the selected day", "applies to every path on this trip", "Spacing and units in Display (D)")
  - locked rows (checked, disabled checkbox + "always on")
- Disclosures (`▶ Weather`, `▶ Saved paths 0 · avoid-areas 0`) look like key rows.

**Spec: four row types**

| Row type | Visual | Content rule |
|---|---|---|
| **Toggle** | checkbox + label, body size, full contrast | Layer name only, from §2.2. No parentheticals. |
| **Locked** | lock glyph (no checkbox) + label + `always shown` | Travelers & chaperones, Reported incidents, Hotel. Never a disabled checkbox. |
| **Key** | swatch + meaning, small, dim, indented under its toggle, shown only when on | **Only what the mark means** (`Saved path · long dash`). No behaviour. |
| **Note** | small italic or dim, after the keys, at most one per layer | Behaviour or scope (`Advance shows the selected day's saved paths`; `An avoid-area applies to every path on this trip`). Cross-references become links (`Spacing: Display ›`). |
| **Sub-group** | tri-state checkbox + label + count + chevron (F10) | For Weather only |

### F10 · P1 · Where Weather and the saved-paths index belong
**Ref:** 1600-07 (`▶ Weather` under Hazards; `▶ Saved paths 0 · avoid-areas 0` under Paths); `weatherGroup` page.js:2335, `savedIndex` page.js:2066.

**Problems**
- **Weather** holds four real toggles (Lightning, Precipitation now, Rain & snow totals (24 h), Cloud cover (forecast)). They are hidden behind a disclosure styled like a key line, so the user can't tell it's a set of layers.
- **Saved-paths index:** a navigation list of objects (click opens the saved-path card) placed inside a visibility control, at the bottom of the longest group. Layers answers "what is drawn"; the index answers "what have we planned". It is also the only Live-mode route to a saved path besides clicking the line on the map.

**Spec**
- **Weather:** keep it under **Hazards** (lightning and precipitation are hazard observations; this also keeps to five groups). Make it a **sub-group row**: tri-state checkbox `Weather overlays` + `0 of 4 on` + chevron.
  - When expanded, the four toggles use normal toggle rows. Each data note (`MET Norway · fetched 07:40`) becomes a note row.
  - Cloud cover is not a hazard. Label it `Cloud cover (forecast, context)` so its presence in Hazards is explained, and list it last.
- **Saved-paths index:** move it to the **rail › Safety & paths** body as `Saved paths ({n})` and `Avoid-areas ({n})`, grouped by day as today. Advance keeps its per-stop `SAVED PATHS · DAY n` list (same rows).
  - In Layers, the two toggles carry the counts: `Saved paths (0)` and `Avoid-areas (0)`. The empty state ("None yet · plan your own path from a place card or the Advance brief") moves with the index.

### F11 · P1 · The Layers / Display split: grid and elevation are spread across both popovers
**Ref:** 1600-07 (Site › `Scale grid` key "Spacing and units in Display (D)"), 1600-08 (Display › `GRID & ELEVATION`, "Turn them on or off in Layers › Site (G · E)", Units / Grid spacing / Contour interval, MOTION, Keyboard shortcuts).

Resulting Display: `UNITS` · `MOTION`. That is small but coherent, and it has room for future view preferences (label density, wall-display mode, plan view). Both cross-reference notes disappear.

## Proposed vocabulary additions (06 §12, Phase 5)

| Term (as shown) | Meaning | Never say |
|---|---|---|
| `To` / `From` (path row labels) | The variable end of a path on a card. The kicker names the fixed end. | "Where", "Destination:", "Origin:" |
| `PATH FROM THIS PERSON` · `PATH TO THIS PLACE` · `PATH TO THIS SITE` | Path section kickers, one per card kind | "PATH HERE", "Route" |
| `Show` + `Walking path` / `Driving path` | Action buttons that request a suggested path. Pressed state: `Walking path · shown`. | bare "Walk"/"Drive" as actions, "Go", "Navigate", "Route" |
| `or Plan your own path…` | Link to the path editor, third in order | "Draw", "Custom route" |
| `Rally point (primary)` / `Rally point (secondary) · not approved` | Rally endpoints, the same strings as the rail | "nearest rally point (draft)" |
| `Nearest hospital` | Nearest by straight line; tooltip says so | "closest ER", "best hospital" |
| `Group center · {n} people` | Median of current positions at this site (≥ 3) | "centre", bare "(19)" |
| `{Name} · last selected` | A person endpoint not currently selected | "From selected person" when nobody is selected |
| `Unaccompanied or outside group zone` | Needs-attention group | "Alone…" (ZON-06) |
| `Rooming & assembly plan` | The trip's floor, chaperone and assembly info in the incident panel | "Hotel card" (taken by the GROUP HOTEL selection card) |
| `street path not checked` | Advance straight-line caveat | "route not checked" |
| `Switch to {site}` | Rebuild the twin at another site (Advance, Sites) | "Go to {site}" |
| `Saved paths ({n})` · `Avoid-areas ({n})` | Layer toggles and rail index entries with counts | "Saved paths (operator)" |
| `Weather overlays · {k} of 4 on` | Weather sub-group row in Layers › Hazards | bare "Weather" disclosure |
| `always shown` (with lock glyph) | Locked layer | "always on" with a disabled checkbox |
| `NOW` / `DETAILS` / `FLOORS` / `CHECKS` / `ACTIONS` | Card section kickers (F5) | instruction text inside a kicker |
| Popover / Panel *(design vocabulary, not on screen)* | Light-dismiss transient surface / persistent surface (F4) | "drawer" for Prototype |
