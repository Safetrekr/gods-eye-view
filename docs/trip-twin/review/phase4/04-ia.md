# 04 IA review, phase 4: Custom paths

Owner: information architect. Review only; no code changed.

**Inputs**
- Shots: `review/phase4/shots/` (1600-01…11, 1280-07), `1600-text.json`.
- Markup and wiring: `twin.html` (#tt-editor, #tt-edit-banner, help), `tripTwin/page.js` (GROUPS/KEY, renderCustom, selectSaved, selectArea, onEdit, Advance "Plan your own path" and SAVED PATHS, keydown), `twinPathEditor.js`, `twinCustomPaths.js`, `twinHud.js` (renderRouteSection), `twinAdvance.js` (briefText).
- Plans: PHASE-4-PLAN, 06 §3 PTH, §9, §10; phase-3 `04-ia.md` and `00-FIX-LIST.md`.

**Not reopened.** These stand:
- one edit at a time;
- the editor owns map clicks;
- avoid-areas are circles with 50/100/200 m sizes;
- Valhalla first, with the OSRM fallback checked and named;
- prototype storage stays in the browser;
- "path" (never "route") in operator copy.

## Verdict

The object model is mostly right:
- A **saved path** is a persistent trip object with an author, a review state and a card.
- An **avoid-area** is a trip-wide object with its own card ("AVOID-AREA · WHOLE TRIP").
- The editor is a temporary mode with a banner and a panel in the right column, where the selection card would be. That is the right home: it replaces the card it came from and keeps the rail and the Advance panel visible.
- The checks are honest. Examples: "No checks raised (not a verification of the path)", "OSRM fallback · avoid-areas checked, not applied".

Three P0s:
1. A saved-path line says **"avoids construction"** for a path that **enters** the construction area. That line goes into the copied brief.
2. There is **no single place that lists saved paths**. A path is found only by spotting its line on the map, or through one stop's brief, and some paths appear in no brief.
3. **Esc and Enter destroy or commit work without warning.** Esc inside the name or notes field throws away the whole path. Enter on any focused button saves. Starting another edit silently discards the current one.

The P1s cover:
- four verbs for one action, one of which ("Edit this path") doesn't edit;
- "draft" meaning three things;
- default names that carry facts which go stale;
- avoid-areas that are trip-wide but managed only inside a per-path tool;
- Live drawing every day's saved paths;
- the brief not tying a saved path to its leg;
- the A key meaning two things.

## Findings

### P0-1: "avoids construction" is printed on a path that enters the construction area

**Evidence**
- 1600-07 and 1600-08 card: `1.9 km · walk 30–39 min (group pace) · avoids construction · ENTERS 1 avoid-area · draft · not reviewed`, directly above `Enters 1 avoid-area: Construction — avoid-areas could not be applied by the router`.
- `savedPathLines` (twinCustomPaths.js l.256, l.263) prints `avoids {reason}` for every area in force when the path was saved (`areaIds`), whether or not it was avoided.
- Unit test l.160 locks in the contradiction: `avoids poor lighting · ENTERS 1 avoid-area`.
- `briefText` (twinAdvance.js l.379) copies the line verbatim into `- Saved path: …`.

**Problem.** The operator, or a chaperone reading the copied brief, takes "avoids construction" at its word. The fact is the opposite. This is the "label claims safety" failure that 06 PTH-01 bans.

**Fix.** Build the phrase from what happened, never from what was in force:

| Case | Text |
|---|---|
| Valhalla and not entered | `routed around: construction` |
| Fallback and not entered | `avoid-areas not applied (fallback) · checked: none entered` |
| Entered | `ENTERS avoid-area: construction (near {nearest site short})`. Never combine with "routed around" for the same area. |
| Stop inside an area | `start/end/waypoint inside avoid-area: crowd / event · not avoided` |

- Update test l.160.
- Lint: the word "avoids" never appears in a line that also contains "ENTERS".

### P0-2: There is no single place to find a trip's saved paths, and some paths are in no list at all

**Evidence**
- Saved paths are reached in only two ways:
  - (a) clicking the dashed line on the map (`twin-saved:` pick, page.js l.500);
  - (b) the Advance stop brief `SAVED PATHS · DAY N` (page.js l.1438–1460).
- (b) lists a path only when one end is within 300 m of **that stop's** site (`siteKeysFor`, l.1609–1615) **and** the day matches.
- A path between two non-site places (rally point → hospital, or from a person's position) gets `siteKeys = []`. It appears in no brief, ever.
- A Live-saved path has `Any day` (1600-02 default; 1600-07 has no day). It shows only under a stop at the hotel, which in the sample is Day 1 "Arrive", under a header that says `DAY 1`.
- Layers › Paths has one row, `Saved paths (operator)` (1600-08), with no count and no list. Turning it off hides every saved path with no trace. In Advance, paths for other days are filtered out of the map (l.1598–1606).
- The plan (C) specified `Saved paths · Day N` rows; phase-3 P1-9 asked for `Saved paths · Day 2 (2)`.

**Problem.** The core findability question, "what paths have we planned for this trip or this day?", has no answer surface. In an incident the operator needs the planned walk back from the concert. Today they must remember which stop's brief it hangs off, or find it on the map. Paths can be orphaned silently.

**Fix.** Make Layers › Paths the one index, since `L` reaches it in both modes, and make each count a link.

```
PATHS
☐ Paths to rally point (suggested)
☑ Saved paths · today (Day 1) · 0
☑ Saved paths · any day · 1        ▸
☐ Saved paths · other days · 1     ▸  (shown in Advance on their day)
☑ Avoid-areas · 1                  ▸
```

- Each `▸` expands rows such as `Fairmont Austin → Dell Seton · walk · not reviewed`. Clicking a row opens `selectSaved(id)` and frames the path.
- In Advance the first row reads `Saved paths · Day 2 (selected) · 1`.
- The brief stays the per-stop view, not the index.
- Add `All saved paths on this trip (2) — Layers` as a link under every brief's SAVED PATHS block.
- A path with no site end is still listed, under its day.
- The 3-click check: `L` → expand → row = 2 actions to any saved path.

### P0-3: Esc and Enter in the editor discard or save without asking, unlike Esc everywhere else

**Evidence**
- `handleKey` checks `Escape` **before** the input guard (twinPathEditor.js l.426–433). Esc while typing the name or the notes closes the editor and drops every waypoint.
- `Enter` saves whenever focus is not in an input (l.439–442). With focus on `↑`, `×`, `Drive` or `Cancel (Esc)`, the keydown is preventDefault-ed and the path is **saved** instead of the button acting.
- `start()` calls `close()` on any open edit (l.404). Clicking `Draw your own path`, `Plan your own path`, `Edit` or `Duplicate` mid-edit silently discards the unsaved path.
- An avoid-area added during the edit is persisted at once (l.309–317). `Cancel (Esc)` does not remove it, yet the button reads as "undo this session".
- After a cancel, the card the operator came from is not reopened (`onClose(null)`, page.js l.1647).
- Everywhere else, Esc steps back one level and "never exits" (help, twin.html l.356–359).

**Problem.** Esc is the operator's universal "back". Here it is "destroy", and it fires from inside a text field. Enter on a focused control commits a path the operator did not mean to save. Saved paths go into briefs, so this is an integrity problem, not polish.

**Fix.** One Esc ladder, one step per press:
1. In a field: leave the field (blur).
2. Placing an avoid-area: stop placing.
3. Avoid-area form open: close the form.
4. Unsaved changes: banner reads `DISCARD THIS PATH? · Esc again to discard · Enter to save`. This reuses `confirmOnce`, 4 s.
5. Nothing changed: close and **reopen the origin card** (place, saved path, or the Advance stop).

Other changes:
- Rename the button `Cancel (Esc)` to `Discard`.
- Enter saves only when focus is on the map, the body or the Save button. Native Enter is kept on every other button.
- Starting another edit while one is open shows, in the banner: `You are editing "{name}" — save (Enter) or discard (Esc) first`. Nothing is discarded.
- Under `Add avoid-area`, add the note: `Avoid-areas are saved to the trip at once; discarding this path keeps them.`

### P1-4: Four verbs open the editor, and "Edit this path" doesn't edit the path shown

**Evidence**
- Place card, idle: `Draw your own path` (twinHud.js l.997; 1600-01).
- Path card, ready: `Edit this path` (l.1031).
- Advance: `Plan your own path` (page.js l.1399; 1600-09).
- Saved card: `Edit` and `Duplicate` (l.1710–1711).
- `onEdit` (page.js l.1030–1040) **clears** the suggested path and asks Valhalla again from the same two ends. The line can change shape, and Primary and Alternate collapse into one.
- "Draw" suggests freehand drawing, but the router draws the line.
- The plan's `New path` in the site card, and the rally-path entry, are not built. There is no way to plan a path *from* a venue, or the walk *back*.

**Fix.** One creation verb, one edit verb:

| Where | Label |
|---|---|
| Place card (idle), path card (ready), Advance stop | `Plan your own path` (on the path card, title `Starts from the same two ends; the suggested path stays as a guide`). Keep the suggested line drawn dimmed while editing. |
| Site card (new) | `Plan a path from {site.short}` |
| Advance stop (see P1-9) | `Plan path · out` · `Plan path · back` |
| Editor (new button) | `Swap start and end` |
| Saved card | `Edit saved path` (title `Saving clears its review`) · `Duplicate` |

### P1-5: "Draft", "suggested" and "reviewed" each mean more than one thing

**Evidence**
- The editor kicker for an *unsaved* path is `NEW PATH · DRAFT` (l.116).
- A *saved* path is `SAVED PATH · DRAFT · NOT REVIEWED` (page.js l.1746).
- A place that is *not approved* is `Draft · not approved` (Layers key, 1600-08).
- The editor calls the operator's own path `Suggested · unverified · Valhalla (FOSSGIS)` (l.164).
- 06 PTH-01 and §10 reserve "Suggested path" for SafeTrekr's computed line.
- The footer reads `Paths stay suggested and unverified until someone reviews them` (l.284). That implies a review verifies the path, which contradicts 06 §10: "a review is a person's check, not an approval".

**Fix.** Three lifecycle states and one name each. Drop "draft" from paths entirely, so it keeps one meaning: an unapproved place.

| State | Kicker / label |
|---|---|
| Computed on demand, not saved | `Suggested path` (unchanged) |
| In the editor | `NEW PATH · NOT SAVED` · `EDITING SAVED PATH · CHANGES NOT SAVED` |
| Saved | `SAVED PATH · NOT REVIEWED` · `SAVED PATH · REVIEWED BY {name} · {date time}` |

- Engine line: `Router: Valhalla (FOSSGIS) · street network only · not checked on the ground` / `Router: OSRM (fallback) · avoid-areas not applied — checked instead`.
- Footer: `Saved in this browser for this trip (prototype). A review records your check; it does not verify the path.`
- Edit kicker sub-line, when reviewed: `Saving clears the review (reviewed by you · Fri 16 Oct 00:01 CDT)`.

### P1-6: The default name carries facts that go stale and uses the long OSM name; the crumb repeats the site

**Evidence**
- `defaultName` = `{fromLabel} → {toLabel} · Day N · walk` is set once at `start()` (l.407–409).
- Switching to Drive (l.133–137) or changing Day (l.254–257) leaves the name unchanged. A drive path saves as `… · walk`, and a path moved to Day 3 still says `Day 2`.
- `toLabel` is the full OSM label: `Fairmont Austin → Ascension Dell Seton Medical Center at The University of Texas · walk` (1600-07, 93 characters). Phase-3 P2-12 says `short` is used in chrome.
- Crumb at 1280 (1280-07): `Fairmont Austin ▾ › Fairmont Austi…`. It reads as the site twice.
- While editing, the crumb still shows the place (1600-02); editing is not visible in the crumb.
- `Duplicate` makes `… · walk (copy)`.

**Fix**
- The name holds words only. The default is `{from.short} → {to.short}`, for example `Fairmont Austin → Dell Seton`. Regenerate it until the operator types.
- Day, mode and leg are facets rendered from fields, in a sub-line on the card, list and brief: `Walk · Day 2 · out`.
- OSM places need a `short`, as phase-3 P2-12 asked (`Dell Seton Medical Center`).
- Crumb focus with a type prefix:
  - `› Saved path: Fairmont Austin → Long Center`
  - while editing: `› New path (not saved)` or `› Editing: {name}`
- The focus segment ellipsizes first, per the phase-3 collapse order.

### P1-7: Avoid-areas are trip-wide but managed only inside one path's editor, with no place, time or confirmation

**Evidence**
- The only list is `AVOID-AREAS ON THIS TRIP · N` inside the editor (l.213–235).
- Its `×` removes the area **for the whole trip** immediately (l.338–344, title only). The map card asks once (`confirmOnce`, page.js l.1780–1797). That is two behaviours for one action.
- List text is `Construction · 100 m` (`areaLabel`). Two construction areas cannot be told apart, and the label has no location and no date.
- Saved paths store `areaIds`. When an area is later added, moved or removed, nothing tells the saved path's card that its basis changed.
- `Crowd / event` and `Poor lighting` are time-bound by nature, yet they apply to every path on every day.
- Map label `Avoid · Construction`, list `Construction · 100 m`, card name `Construction · 100 m` under `AVOID-AREA · WHOLE TRIP`: three patterns.

**Fix**
- **Home:** Layers › Paths › `Avoid-areas · N ▸` list (P0-2) plus the avoid-area card.
  - The editor list becomes read-only: rows plus `Add avoid-area (X)`, with a line `Remove an area from its card or Layers`.
  - Removal happens only from the card, with confirm-once.
- **One label pattern:** `Avoid-area · Construction · 100 m · 150 m N of Fairmont Austin`. The card adds `Added by you · Fri 16 Oct 00:00 CDT`. The map label is `Avoid · Construction`.
- **Scope field** in the add form: `Applies: Whole trip (default) · Day {n} only`. A day-only area is labelled `· Day 2 only` and is ignored by other days' paths.
- **Basis changed:** when the areas change after a path is saved, the saved card and brief line add `Avoid-areas changed since saved · re-plan (Edit saved path)`.

### P1-8: Layers draws every day's saved paths in Live, not per day, and a selected saved path looks like a suggested one

**Evidence**
- `renderCustom` filters by day only in Advance. Live draws all saved paths on every day (page.js l.1598–1606). The key admits it: `Advance shows the selected day` (l.1869).
- The selected saved path in 1600-10 and 1280-07 is drawn as a bright, near-solid line with chevrons. That is the `Suggested path` swatch, not the `long dash` swatch.
- Both `Alternate` and `Saved path` are blue dashes in the key (1600-08).
- The row `Suggested walking paths` still toggles only the rally path (phase-3 P1-9 rename not done).

**Fix**
- Live draws today's paths plus any-day paths. Rows as in P0-2. The key reads `Saved path · long dash · Live: today · Advance: the selected day`.
- A selected saved path stays long-dashed (brighter or thicker, never solid) and carries a midpoint label `Saved · Fairmont Austin → Long Center`. The difference is in the label and the dash, not only the colour.
- Rename the rally row `Paths to rally point (suggested)`.

### P1-9: The brief doesn't tie a saved path to its leg, and contradicts it

**Evidence**
- 1600-10: Day 2 has `SAVED PATHS · DAY 2 · 1 · Fairmont Austin → Long Center …`. On the same stop, `From the hotel` still reads `1.3 km W straight line … · route not checked`.
- `Plan your own path` always plans hotel → stop (page.js l.1397–1411). The risky `ends 21:30 — the walk back is in the dark` leg cannot be planned from Advance.
- Records hold `day` only, not `event_id` or `leg` (`savedPathRecord`, l.219–240). Phase-3 P1-8 specified keys `${event.key}:out|back:${profile}` and the leg status ladder.
- `route not checked` is a G10 leftover.

**Fix**
- Record `event_id` and `leg` (`out`, `back` or `other`).
- Replace `From the hotel` with leg items whose status climbs the ladder:
  - `Hotel → Long Center · arrive by 19:00 · saved path · not reviewed`
  - `Long Center → hotel · after 21:30 · after dark · straight line only · path not checked`
- Buttons: `Plan path · out` / `Plan path · back`.
- In the SAVED PATHS block, group lines `Out · Back · Other`. Any-day paths carry `· any day`.

### P1-10: A means "avoid-area" in the editor and "needs attention" in Live; help has no editor keys

**Evidence**
- The editor takes the keyboard first (page.js l.2464). `A` arms an avoid-area (l.434–437), while in Live `A` = first attention item (l.2548; help l.332).
- Every other key is swallowed while editing (l.447): `?`, `L`, `1 2 3`, `, .`, `N`, `F`. During a long edit the operator can't open help or Layers, or turn the view.
- `Backspace` (remove the last waypoint) is in neither the banner nor the help.

**Fix**
- Avoid-area key = **`X`** (exclude, matching Valhalla's `exclude_polygons`). Button `Add avoid-area (X)`. Banner: `EDITING PATH · click the map: add waypoint · click a waypoint: remove · Backspace: remove last · X: avoid-area · Enter: save · Esc: back`.
- In the editor, `A` shows the status `A is "needs attention" — finish (Enter) or discard (Esc) the path first`.
- View-only keys pass through while editing: `?` `L` `D` `1 2 3` `, .` `N` `F` `G` `E`.
- Help gets a group `WHILE EDITING A PATH` listing the rows above, plus the P0-3 Esc ladder.

### P2-11: Reasons list

**Evidence.** `AVOID_REASONS` = `Construction · Crowd / event · Poor lighting · Traffic · Other` (l.8–14). `Other` saves with no note.

**Problems**
- "Traffic" is unclear for a walking path.
- A demonstration (security-relevant, and often in official advisories) is folded into "Crowd / event".
- There is no reported closure or flooding.
- `Other` can be saved blank.

**Fix.** Use: `Construction / works · Crowd / event · Demonstration · Busy road or crossing · Poor lighting (after dark) · Closure or flooding (reported) · Other (note required)`.
- `Poor lighting` defaults its scope to the day and applies only to legs flagged after dark.
- Never "unsafe", "danger" or "blocked", unless an official closure is cited, per 06 PTH-06.

### P2-12: Waypoints are raw coordinates

**Evidence.** `1 · 30.26356, -97.73866` (1600-03); avoid form `Centre 30.26458, -97.73826` (1600-04).

**Fix**
- Waypoint row: `1 · Cesar Chavez St at Congress Ave`, from the Valhalla maneuver street names. Fallback: `1 · 140 m SW of Fairmont Austin`. Coordinates go in a tooltip.
- Avoid form: `Centre · 150 m N of Fairmont Austin`.
- Map markers use the same numbers.

### P2-13: SOC readiness (multi-trip, authorship, sharing with chaperones)

**Evidence**
- Storage key `paths.${cityKey}` = `paths.austin` (page.js l.89, l.1586). Two trips or scenarios in one city share paths and avoid-areas, yet the footer says "for this trip".
- `siteKeys` are city keys, not `place.id` (phase-3 P2-14).
- `stamp` = `you · Fri, 00:01 CDT` (l.1178), with no date. A brief written a week ahead gives an ambiguous "Fri".
- The copied brief exports `reviewed by you`. To a chaperone, "you" is the reader.
- The export line has no via-streets, no notes and no avoid-area locations, so a chaperone cannot follow "2.0 km · walk".

**Fix**
- Key paths and areas by `trip_id`, sites by `place.id`.
- Stamp: `{operator name} · Fri 16 Oct 00:01 CDT`. In the prototype export, write `reviewed by operator (this browser)`.
- Export line: `- Saved path · out · Fairmont Austin → Long Center · walk 2.0 km, 32–41 min · via Cesar Chavez St, S 1st St · routed around: construction (150 m N of Fairmont Austin) · after dark · reviewed by {name} {date time} · notes: …`.
- Chaperone-facing exports include **reviewed** paths only, with drafts listed as `not reviewed — do not share`.
- Record in 07:
  - `saved_paths(id, trip_id, event_id, leg, profile, name, waypoints, geometry, engine, avoid_applied, area_ids, notes, saved_by, saved_at, reviewed_by, reviewed_at, version)`
  - `avoid_areas(id, trip_id, center, radius_m, reason, note, scope_day null, added_by, added_at)`
  - GPX or map-link export for the chaperone app (production).

### P2-14: 06 has no §11, and phase-3 leftovers remain

**Evidence**
- The plan lists `06 (§11 vocabulary)` as changed, but 06 ends at §10.
- Leftovers:
  - `route not checked` (1600-09 brief);
  - `37 floors · US numbering · lobby = 1` (1600-09 hotel card; banned by phase-3 P2-13);
  - `Suggested walking paths` (P1-8).

**Fix.** Add 06 §11:

| Term (as shown) | Meaning | Never say |
|---|---|---|
| Saved path | Operator-planned path stored on the trip | "custom route", "approved path" |
| New path · not saved / Editing saved path · changes not saved | Editor states | "draft" (reserved for unapproved places) |
| Not reviewed / Reviewed by {name} · {date time} | A person's check of the line, not a verification | "verified", "approved", "safe" |
| Plan your own path / Edit saved path | The two editor verbs | "draw", "edit this path" (for a suggested path) |
| Avoid-area · {reason} · {size} · {where} | Trip-wide (or day-only) area that paths are routed around | "no-go zone", "danger zone", "blocked" |
| Routed around / ENTERS avoid-area | Outcome per area | "avoids" (ambiguous) |
| Out · Back · Other | Leg of a saved path | "return route" |
| Router: Valhalla / OSRM (fallback) | Engine line | "verified by" |

## What works — keep

- **Saved paths and avoid-areas are first-class objects.** Each has its own card, a kicker (`SAVED PATH · …`, `AVOID-AREA · WHOLE TRIP`) and a map pick. The avoid-area card says `Applies to every path planned on this trip · used by N saved paths`.
- **The editor's home.** It replaces the selection card in the right column, puts a banner across the map, leaves the rail and the Advance panel untouched, and never moves the camera on its own.
- **Honest checks.** `No checks raised (not a verification of the path)`. The fallback is named with its reason (`no path avoids every area — … move or shrink one`). Stops inside an area are excluded and named. `Walked after dark at the planned time`. `1.8×` and `does not reach` flags.
- **Editing a saved path clears its review** (twinPathEditor l.376–377). Tell the user so (P1-5).
- **Delete and remove ask once.** The `click again to confirm` pattern is consistent across the cards; extend it to the editor (P0-3, P1-7).
- **Review is a person's action with a stamp,** and the brief line carries `not reviewed` or `reviewed by`.
- **Saved paths flow into the brief and the copy** (`- Saved path: …`). Once keyed by leg, that slot is the right one.
- **Trip-wide avoid-areas.** Applying one area to every path (and re-checking older paths against it) is the correct model. Add a day scope; don't make it per path.
- **"Path" vocabulary** holds in all phase-4 copy. Only the phase-3 `route not checked` leftover remains.
