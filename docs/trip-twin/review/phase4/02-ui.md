# Phase 4 · UI / visual review (custom paths)

Reviewer: factory-ui-designer · 16 Oct 2026 · review only, no code touched.

**Inputs**
- `00-CONTEXT.md` (COLOR AND BRAND), `PHASE-4-PLAN.md`, `review/phase3/02-ui.md`, `review/phase3/00-FIX-LIST.md`
- `tripTwin.css`: the phase-4 section (lines 1786–1894), plus the base `.tt-btn`, `.tt-x`, `.tt-rcol` and input rules it relies on
- `twinCustomPathsLayer.js`, `twinPathEditor.js` (editor DOM and banner copy), `twin.html` (right-column order), `tripTwin.js` (`setPickHandler` → crosshair cursor)
- Screenshots: 11 states × 1600×900 and 1280×720 in `shots/`, plus `1600-text.json` and `1280-text.json`. Zoomed crops were taken of 1600-03 (waypoint), 1600-07 (avoid-area), 1600-08 (legend) and 1600-10 (dashes).

**How contrast was measured.** WCAG 2.x ratios, computed from the tokens and blended over `--tt-card #07212c` or the field `#061a23`. "Lit glass" means `#3e545d`, sampled from the hologram behind the banner in 1600-02. Worst-case scene-label plates are blended α 0.88 over `#eff7f3` (white glass edges).

## Verdict

Phase 4 fits the product's visual language:
- blue means paths;
- amber means attention / avoid;
- pink appears only on Delete and on hazards;
- no green is used on anything an operator draws.

The avoid-area disc, with its amber outline and `Avoid · Construction` plate, reads well over the hologram (label 8.0:1 worst case). The saved-path card keeps the phase-3 honesty copy.

The editing mode is not yet a distinct, deliberate mode:
1. **The edited path looks like the suggested rally path.** Both are drawn in the same blue glow at full strength. The edit path's end is never in frame (all 22 frames).
2. **A crossing is shown badly.** On a crossing, the whole edit line turns amber and merges with the amber disc. The saved card then claims the path "avoids construction" in the same line that says it "ENTERS 1 avoid-area".
3. **Waypoint numbers do not render.** Waypoints are dark dots with no digit.

On top of that:
- the banner is a two-line mono sentence that looks like another chip;
- the name input and the saved card's buttons truncate or overflow at 1280;
- the top bar's focus crumb repeats the site name and then cuts off (`Fairmont Austi…`).

Nothing flashes and the camera never moves by itself.

## Findings (ranked)

### P0-1 · The path being edited is not isolated: same blue glow as the suggested rally path, other paths at full strength, End never in frame
**Evidence**
- **Same look.** In 1600-09 and 1280-09 (Advance, new path to Long Center), the edit path runs west from the hotel as a blue glow line. The standing rally path runs south-west as the same blue glow line, and the old saved path shows long-dashed to the north. From the scene alone you cannot tell which line is being edited. 1600-02/-03 and 1280-02 show the same thing.
- **Same code.** In `twinCustomPathsLayer.js` the edit line is `PolylineGlowMaterialProperty #3b82f6, width 5`. That is the suggested-path grammar.
- **End off-screen.** The destination is off-screen in every editor frame (1600-02 to -06, 1600-09, and the 1280 equivalents). `End · …` is never visible, and the editor has no "Frame path" control (the editor text in `1600-text.json` has none).

**Problem:** The operator is drawing a path that will go into a responder brief. They have to see which line is theirs and where it ends. The film reference's whole point is that the subject is isolated and its surroundings dimmed.

**Fix**
- **Edit line: give it its own grammar.** Use a blue core with a white edge. White already means "selected / focus" in this view.
  ```js
  width: 6,
  material: new Cesium.PolylineOutlineMaterialProperty({
    color: css('#3b82f6', 1), outlineColor: css('#eff7f3', 0.9), outlineWidth: 1.5 }),
  ```
  The white edge on blue measures 3.37:1, and it stays distinct over lit glass, where plain blue is only 2.17:1.
- **Dim everything else while editing,** following G11: the standing rally path, any on-demand path, and saved paths that are not being edited.
  - Draw them at α 0.30.
  - Hide their chevrons and labels.
  - Restore them on Save or Cancel.
- **Add `Frame path (F)` to the editor** as a `.tt-tb` beside Walk / Drive. Reuse G11's Frame-path / safe-area framing. It is an operator action only.
- **End off-screen:** when the End is still outside the safe area, show the phase-3 edge chip: `End · Dell Seton · 1.9 km N ↑`, which is static.

### P0-2 · A crossing is misrepresented: the summary says "avoids construction" for a path that enters it, the whole edit line turns amber, and saved paths show no crossing on the map
**Evidence**
- **Contradictory copy.** 1600-07 and 1280-07 show the saved card line: `1.9 km · walk 30–39 min (group pace) · avoids construction · ENTERS 1 avoid-area · draft · not reviewed`. Its amber flag directly below says `Enters 1 avoid-area: Construction`.
- **Whole line amber.** In 1600-05/-06 and 1280-05 the entire edit line is amber (`warn ? '#f59e0b'`), not just the part inside the disc. In the Layers legend, amber dashed already means "Within 1 km of a heat detection" (1600-08). The flagged edit path therefore reads as a heat-proximity path, and it merges with the amber disc it crosses.
- **No crossing on the saved line.** In 1600-07 the saved path runs straight through `Avoid · Construction` as an ordinary long dash. Nothing on the map shows the crossing.

**Problem:** "Avoids construction" on a path that enters the construction area is a false safety statement. It would be copied into a brief. Recolouring the whole line also hides where the problem is.

**Fix**
- **Copy.**
  - Remove "avoids …" from the summary. The summary line becomes only `1.9 km · walk 30–39 min (group pace)`.
  - Add one status line under it. With Valhalla and no crossing: `Avoid-areas applied: Construction (100 m)` in `--tt-text-2`. With a crossing, the amber flag (existing `.tt-edit-flag`): `Enters avoid-area: Construction (100 m)`, followed by an action line in `--tt-text-2`: `No walking path avoids it — move or shrink the area, or add a waypoint around it.`
  - No uppercase words inside sentences.
- **Map, edit and saved paths.**
  - Keep the line blue (P0-1).
  - Overlay only the crossing segments. Use width 8 at height `base + 1.8`, with `PolylineDashMaterialProperty({ color: css('#f59e0b'), gapColor: css('#061a23', 0.9), dashLength: 10 })`.
  - At the entry point, add an amber point of 10 px and a plate reading `Enters avoid-area`.
  - Amber on blue is only 1.71:1, so the dark gaps and the dash pattern carry the meaning for colour-blind users, not hue.
  - Draw the same overlay on saved paths whenever they are shown.
- **Legend.** Under "Saved paths", add the row `Enters an avoid-area` with an amber/dark dash swatch.

### P1-3 · Edit mode reads like another chip: a two-line mono banner, no state in the top bar
**Evidence**
- **Wraps to two lines.** The banner wraps at 1600 (1600-02, `Esc cancel` alone on line 2) and at 1280 (1280-02, `… · A` / `avoid-area · Enter save …`, which splits the key from its action).
- **Looks like a chip.** It is set in mono 11 px blue with a 1 px blue border, the same visual weight as the chips row above it. It covers the `Rally point (secondary)` / `Fire station` labels under it.
- **Weak border.** The border is `#3b82f6` on lit glass at 2.17:1.
- **No bar state.** The top-bar chip still reads `MONITORING` / `PLANNING` while editing (1600-02, 1600-09).
- **Cursor.** The crosshair cursor is set in code (`setPickHandler`), which is good, but a screenshot can't show it.

**Fix**
- **Copy.** Shorten to one line and move "click a waypoint to remove it" into the panel's WAYPOINTS note:
  `<b>EDITING PATH</b> Click the map to add a waypoint · <kbd>A</kbd> avoid-area · <kbd>Enter</kbd> save · <kbd>Esc</kbd> cancel`
  This is about 470 px at Inter 12 px. It fits the 624 px gap between the rail and the right column at 1280.
  - Arming: `<b>PLACING AVOID-AREA</b> Click the map for its centre · <kbd>Esc</kbd> stop`.
  - Form open: `<b>AVOID-AREA</b> Choose its size and reason in the panel`.
- **Banner CSS:**
  ```css
  .tt-edit-banner { font: 400 12px/16px var(--tt-font); letter-spacing: 0; color: var(--tt-text);
    background: rgba(18, 54, 70, 0.96); /* brand secondary #123646 */
    border: 1px solid var(--tt-path-text); border-left-width: 4px;
    padding: 7px 12px; white-space: nowrap; overflow: hidden; text-overflow: ellipsis;
    top: calc(var(--bar) + var(--g) + 40px); }
  .tt-edit-banner b { font: 600 11px/16px var(--tt-mono); letter-spacing: .08em; color: var(--tt-path-text); margin-right: 8px; }
  .tt-edit-banner kbd { font: 500 11px var(--tt-mono); border: 1px solid var(--tt-edge-ctl); border-radius: 2px; padding: 0 4px; }
  ```
  - Text measures 11.74:1, the tag 6.48:1, and the border `#93bafa` 4.05:1 on lit glass.
  - The filled band and the 4 px rule make it a strip, not a chip.
- **Top bar.** While editing, render `EDITING PATH` right after the mode chip: `.tt-mode.editing { border: 1px solid var(--tt-path-text); color: var(--tt-path-text); }`. It is static and has no pulse.

### P1-4 · Waypoints: the number never renders, the marker is too small, coordinates are used as labels, and the controls are 18 px
**Evidence**
- **No digit.** 1600-03, -05, -06 and 1280-03, -05 all show waypoint 1 as a dark disc with a white ring and **no digit**. The zoomed crop of 1600-03 confirms it. The point and its label share a position, and both have depth testing off, so the point primitive paints over the label.
- **Off the line.** The marker also sits clear of the drawn line (pedestrian snapping), so it looks ignored.
- **Coordinates as names.** The list row reads `1 · 30.26356, -97.73866` in mono.
- **Small controls.** `↑ ↓ ×` are `.tt-x` controls about 18×20 px with 4 px gaps, below WCAG 2.5.8's 24×24. `↑` and `↓` show and do nothing when there is only one waypoint.

**Fix**
- **Marker.** Draw it as one billboard from a canvas, 20×20:
  - fill `#061a23`;
  - 2 px `#eff7f3` ring;
  - the digit in `600 12px Inter` `#eff7f3`, centred (16.3:1);
  - `disableDepthTestDistance: Infinity`.
  - On hover, ring `#93bafa`, `cursor: pointer`, and title `Waypoint 1 · click to remove`.
- **Leader.** When the marker is more than 15 m from the returned line, draw a 1 px `#93bafa` dashed leader to the nearest point on it.
- **List row.** `1 · 140 m NW of Fairmont Austin`, with the numerals in mono and the words in Inter. Put the coordinates in `title`.
- **Controls:**
  ```css
  .tt-edit-list .tt-x { width: 28px; height: 28px; display: inline-grid; place-items: center; padding: 0; border-radius: 3px; color: var(--tt-text-2); }
  .tt-edit-list .tt-x:hover { background: rgba(42, 74, 89, 0.6); color: var(--tt-text); }
  .tt-edit-list .tt-x:disabled { opacity: .35; cursor: default; }
  ```
  Disable `↑` on the first row and `↓` on the last.

### P1-5 · Saved and alternate paths are both blue dashes; saved labels are never on screen; draft and reviewed look the same
**Evidence**
- **Look-alike dashes.** In the 1600-10 crop, the saved path (`#93bafa`, `dashLength 28`) runs parallel to the rally path's alternate (`#3b82f6`, short dash) on the same street. At a glance they are two dashed blue lines.
- **Look-alike swatches.** In the Layers legend (1600-08 crop), the "Alternate" and "Saved by an operator · long dash" swatches are the same `- -` glyph at 16 px.
- **Labels off-screen.** The `Saved · name · draft` label is placed at the geometry midpoint. For 1.9–2.0 km paths that is off-screen in every frame (1600-07, -10, -11; 1280-07, -10, -11).
- **Same line.** Reviewed (1600-11) and draft (1600-10) draw identically.

**Fix**
- **Patterns.**
  - Alternate: `dashLength: 12` (short, 50/50).
  - Saved: `dashLength: 40, dashPattern: 0xFFF0` (75 % on), width 3, `#93bafa`. It then reads as a near-continuous light line with breaks.
  - Add 6 px `#93bafa` end caps on saved paths.
- **Label.** Anchor it 150 m along from the start, so it sits inside the site view. Use `600 12px Inter` (the phase-3 scene-label standard), text `Saved · to Dell Seton · draft` (short name). It measures 6.48:1 worst case.
- **State.** Draft at α 0.75 with "· draft"; reviewed at α 1 with "· reviewed".
- **Legend swatches** at 24 px wide:
  ```css
  .tt-sw.alt   { height: 2px; background: repeating-linear-gradient(90deg, var(--tt-path) 0 4px, transparent 4px 8px); }
  .tt-sw.saved { height: 3px; background: repeating-linear-gradient(90deg, var(--tt-path-text) 0 12px, transparent 12px 16px); }
  .tt-sw.avoid { width: 14px; height: 10px; border: 1px solid var(--tt-attention);
    background: repeating-linear-gradient(45deg, rgba(245,158,11,.45) 0 2px, transparent 2px 5px); }
  ```
  Today the avoid-area swatch is a solid amber line, which matches nothing drawn on the map.

### P1-6 · Editor panel hierarchy: truncated name, duplicate route line, a 4-line engine sentence above the flag, Save below the fold at 1280, 1.6:1 field borders
**Evidence**
- **Truncated name.** The name input is cut at both widths: `Fairmont Austin → Ascension Dell Seton Me` (1600-02) and `…Dell Seto` (1280-02). The next line repeats it in full: `From Fairmont Austin → to Ascension Dell Seton Medical Center at The University of Texas`.
- **Long engine sentence.** In 1600-05 and 1280-05 the dim engine line runs 4 lines (`… (Valhalla: no path avoids every area — the areas block all ways through; move or shrink one)`). The action the operator needs is buried in dim text, and it pushes the amber flag down.
- **Save off-screen.** In 1280-04, with the avoid-area form open, `Save path` / `Cancel` are below the fold with no scroll cue.
- **Empty space.** At 1600 the panel stretches to the full column height and leaves about 250 px empty (`.tt-editor { flex: 1 1 auto }`, 1600-02).
- **Weak field borders.** The name input, Notes textarea and the avoid-area Note input use `--tt-border`, which is 1.61:1 on the field and fails 1.4.11. The selects use `--tt-edge-ctl` (5.67:1). In 1600-04 the Note field is nearly invisible.
- **Weak placeholder.** The placeholder is the UA default `#757575` (3.86:1).

**Fix**
- **Name.**
  - Default to short names, following the plan's own pattern: `Fairmont → Dell Seton · walk` or `Hotel → Long Center · Day 2`. Put the full place names in `title`.
  - Set `.tt-edit-name { font: 600 13px/18px var(--tt-font); text-overflow: ellipsis; }`.
  - Drop the `From … → to …` line unless the name was edited. If it was, show it as one `.tt-dim` line.
- **Order:** kicker, name, `Walk | Drive | Frame path`, **Day**, then the result. Day is part of the path's identity, so it moves up from below the avoid-areas.
- **Result block:**
  - one dim line, `Suggested · unverified · OSRM fallback`;
  - then the flags;
  - then the action line from P0-2;
  - the Valhalla reason goes into the action line's `title`.
- **CSS:**
  ```css
  .tt-editor { flex: 0 1 auto; display: flex; flex-direction: column; }
  .tt-editor > .tt-actions { position: sticky; bottom: -12px; background: var(--tt-card);
    border-top: 1px solid var(--tt-border); padding: 8px 0 12px; margin-top: 10px; }
  .tt-edit-name, .tt-edit-area input[type='text'], .tt-editor .tt-adv-notes { border-color: var(--tt-edge-ctl); }
  .tt-editor ::placeholder { color: var(--tt-text-dim); }   /* 7.26:1 */
  ```
  Apply the F24 `.scrolls` fade mask to `.tt-editor`.

### P1-7 · Saved-path card: "Mark reviewed" wraps in a 32 px button, Delete is clipped at 1280 and sits right beside it, and the kicker wraps
**Evidence**

- **Repeated stamp.** `reviewed by you · Fri, 00:01 CDT` appears twice in 1600-11, once in the summary and once in the provenance line.

  `Edit`, `Duplicate` and `Mark reviewed` total about 252 px and fit the 276 px content width at 1280.
- **Kicker.** `SAVED PATH · DRAFT` or `SAVED PATH · REVIEWED`. Draft already means not reviewed.
- **Reviewed state.** Add one line, `Reviewed by you · Thu 22:21 CDT`, in `--tt-text` with a 2 px `#eff7f3` left rule (15.3:1). Remove the stamp from the summary. Do not use green, because green means approved places of safety.

### P1-9 · Avoid-areas: no preview while choosing the size, soft stripes, an 11 px non-token label colour
**Evidence**
- **No preview.** In 1600-04 and 1280-04 the form shows `Centre 30.26458, -97.73826` and a size select, but nothing is drawn on the map. The operator chooses 50, 100 or 200 m blind.
- **Soft stripes.** The fill (`StripeMaterial`, VERTICAL, repeat about radius/8) renders as 6–7 soft vertical bands (1600-07 crop). It reads as lit glass more than a no-go hatch. The even stripe is 1.7:1 against the field, so the outline (7.54:1) carries the shape alone.
- **Label style.** The label uses `500 11px` and `#f8c471`, which is not a token.

**Fix**
- **Preview.** While the form is open, draw the disc at the selected size with no fill and a dashed amber ring: a polyline circle with `PolylineDashMaterialProperty #f59e0b`, `dashLength 12`. Plate: `Avoid-area · not added yet`. Update it on size change and remove it on Cancel.
- **Hatch.** Use `ImageMaterialProperty` with a 16×16 canvas: a 45° line, 3 px wide, `rgba(245,158,11,.5)` on transparent, `repeat: new Cartesian2(r/6, r/6)`. Minimum fallback: Stripe with `repeat: radiusM/5`, `evenColor α .32`, `oddColor α 0`.
- **3D read (optional).** Add a 6 m outline-only fence (`extrudedHeight: base + 6`, fill α 0.08) so the area reads at grazing angles and behind buildings.
- **Label.** `600 12px Inter`. Add the token `--tt-attention-text: #f8c471` (11.1:1 on the plate, 8.0:1 over white glass). Text: `Avoid · Construction · 100 m`.

### P1-10 · Right column order: the editor sits above the incident panel and takes all spare height (cross-lens; from code, not shots)

```css

.tt-rcol > .tt-editor { flex: 0 1 auto; min-height: 160px; }
```
Add a QA shot: incident plus editor at 1280.

### P2-11 · The Start plate overprints people pins
**Evidence:** In 1600-02/-03/-05 and 1280-02/-05/-09, `Start · Fairmont Austin` is anchored at the site centre, inside the hologram. It covers the SD and LB pins and the floor-ruler `20`.
**Fix**
- Anchor Start at the line's first vertex, where it leaves the footprint.

### P2-12 · Motion and stability: each re-route collapses the result block, so Save jumps
**Evidence:** In code, `status === 'loading'` replaces the whole result block with one line, `Asking the router…`, on every waypoint, mode or area change (debounced 250 ms). The waypoint list, Day select and the Save button move up and back under the cursor, and Save is disabled in between.
**Fix**
- Keep the last result rendered at `opacity: .5`, with `Updating path…` (`aria-live="polite"`) above it.
- Reserve the block's height: `.tt-edit-result { min-height: 72px; }`.
- On the map, keep the previous line at α 0.4 until the new one arrives. Do not animate it.
