# Phase 5b — Information architecture review (04-ia)

Review only. Inputs: shots `review/phase5b/shots/` (1600 and 1280, `1600-text.json`), `06-layer-taxonomy.md` §10–§12, `gods-eye-view/src/operations/tripTwin/` (page.js, twinUnits.js, twinData.js, twinRoutes.js, twinHud.js, twinNumbering.js, twinCutaway.js, twinPeople.js, twinDeclutter.js, tripTwin.js), `gods-eye-view/twin.html` (Display popover, help overlay).

**Verdict.** The structural rule now holds: **Layers = what is drawn + that layer's options; Display = how the whole view presents.** Spacing and interval sit under their layers, units are global, and both match the rule. Four things still need work. (1) The units promise ("every distance on screen") is broken in two places you can see in the shots. (2) One readout in Display, the ground relief range, breaks the rule the day it is set. (3) Go to floor is missing from the one floor stack where it matters most, the incident panel. (4) The site-switch question points to the wrong place. Display should stay, but only once it holds a second unit (temperature). Otherwise it is a two-control popover taking up a toolbar slot.

Priority: **P0** = misleads a safety decision · **P1** = breaks a stated contract or the rule, or blocks a task · **P2** = consistency or polish.
No P0 this round.

## Findings

### F1 · P1 · The units promise has two leaks (shots 01, 02, 03)

**Problem.** In Feet · miles, the path card reads `Showing the drive: 1.7 km in a straight line` next to `1.2 mi · 3–5 min`. An operator comparing "1.7" with "1.2" reads a straight line that is longer than the road route. Layers › Paths › key reads `Within 1 km of a heat detection` (shot 03, feet mode, `Spacing 250 ft` in the same panel). Display says *"Every distance on screen: cards, paths, chips, grid and contours."* That is a contract, and the path card and the Layers key are both on the list.
**Cause.**
- `twinRoutes.defaultMode()` builds the `reason` string once, and `rebuildRouteText()` (page.js) rebuilds `cards` and `other` but not `reason`.
- The Layers `KEY` object is built once at setup, so `formatRadius(1000)` never changes after that.

**Spec.**
- Build every distance string at render time from metres. Store `straightM` on the route model, not the formatted sentence. Build `KEY.paths[2]` inside `renderLayers()`.
- Sensor resolutions are part of a source's name and stay as published: `Heat detection (375 m pixel)`, `Lightning density · NOAA nowCOAST (8 km grid)`, `(2 km)`. Extend the Display note so this is stated, not discovered: `Every distance on screen: cards, paths, chips, grid and contours. Sensor resolutions stay as published.`
- Add a unit lint to the phase tests. With `ft` or `yd` set, rendered text in the card, rail, Layers, chips, incident panel and status bar must not match `/\b\d[\d.,]*\s?(m|km)\b/`, except for the sensor-name allowlist above.

### F2 · P1 · The relief readout sits in Display and breaks the rule (shot 04)

**Problem.** Display › Units contains `Ground in this view: -41 ft to +34 ft vs hotel street level`. This describes the drawn terrain, so it is a fact about the Elevation layer, not a view-wide setting. It also shows when contours are off, and it uses a hyphen-minus and "vs" while the Elevation key and status bar say "relative to".
**Spec.** Move it to Layers › Site › Elevation contours, as the last key line under the Interval row. Show it only when the layer is on:
```
☑ Elevation contours
   ── Contour · relative to hotel street level
   Interval   [ 10 ft ▾ ]
   Ground here: −41 to +34 ft relative to hotel street level
```
Use a true minus sign (U+2212), put the unit once at the end, and use the word "relative to" everywhere (key, status bar, readout).

### F3 · P1 · Does Display earn its toolbar slot? Yes, but only with temperature added (shots 04, 05)

**Problem.** Once F2 is done, Display holds one select (Distances), one checkbox (Reduce motion) and a help link. That is thin for a toolbar button with its own key. There is also a gap that shows up in the UNITS group: temperature follows region, not the operator (`useF = region === 'us'`, page.js). So shot 05 shows `Meters · km` with `64 °F` in the top bar. An operator who picks metric sees mixed units, and the UNITS heading suggests temperature is set here when it is not.
**Spec, Display popover (final):**
```
Display  D                                   ×
UNITS
  Distances     [ Feet and miles (ft, mi) ▾ ]
  Temperature   [ °F ▾ ]          (default by trip region)
  Every distance and temperature on screen: cards, paths, chips,
  grid, contours, weather. Sensor resolutions stay as published.
  Grid spacing and contour interval: Layers › Site (L)
MOTION
  ☐ Reduce motion
──────────────────────────────────────────────
Keyboard shortcuts (?)
```
- The pointer line `Grid spacing and contour interval: Layers › Site (L)` is what brings back operators who learned the old location. It is the reverse of the Layers note (F8).
- Reduce motion has to apply everywhere it is offered. `frameWholeTrip()` (page.js) checks only `prefers-reduced-motion`, not the `tripTwin.reduceMotion` pref that `tripTwin.js` uses. Route it through the same `reducedMotion()` check.
- If temperature is not added this phase, fold Display into the top-right `?` menu as "View settings" and give the toolbar slot back. Do not keep a popover whose only setting is distances.

### F4 · P1 · The Go to floor message: "check the numbering" points to nothing you can act on (shots 05, 06)

**Problem.** `Floor 52 is not in this building (1–37) — check the numbering`.
- "The numbering" is not a labelled thing on this card. The card line reads `37 floors · US numbering · lobby = 1`.
- For a mapped building there is no control to change the numbering (mapped places are never overridden, twinNumbering.js), so the instruction cannot be followed.
- §10 already has the term for this case: `Outside this building's floors`.
- The floor-numbering wording appears in three forms:
  - Hotel card: `US numbering · lobby = 1` / `ground floor = 0`
  - Form: `Ground floor = 1 (US)`
  - Note: `Floor numbering: ground floor = 1 · top floor 9 · operator entry, not verified`

**Spec.**
- Message for a mapped building: `Floor 52 is outside this building's floors (1–37).`
- Message for an operator entry: `Floor 52 is outside this building's floors (0–9). Numbering is an operator entry, not verified ·` [`Change numbering`]. The link opens the existing numbering form.
- One numbering line on the hotel card, in the same shape whatever the source:
  - `Floor numbering: ground floor = 1 (US) · floors 1–37 · mapped`
  - `Floor numbering: ground floor = 0 · floors 0–9 · operator entry, not verified` [`Change`]
  - `Floor numbering not verified` (unchanged)
  
  Drop "lobby = 1": the lobby is not always the ground floor.
- Field: the visible label stays `Go to floor`. Add placeholder `as on the lift` so the visible text matches the report form's `Floor (as the hotel numbers it)` and the aria-label. The button stays `Go`.
- Keep the field above the stack (correct for a 37-row list) and clear it on success (done).

### F5 · P1 · Go to floor is missing from the incident panel's Floors (shots 08, 09)

**Problem.** During an incident the floors move to the incident panel (`docked`, compact). The `goFloor` form is only added to the hotel-card `cutBox` (page.js). The compact stack squeezes quiet floors to as little as 1 px with no labels (twinCutaway.js `quiet` / `compact`). Shot 08 shows `37`, then `11` down to `3`, so floors 12–36 cannot be clicked. That is the moment a caller says "we're on 23".
**Spec.** Use one `Go to floor` control per floor stack, in the same position in both: directly under the `FLOORS` kicker, above `Select a floor to see who may be on it`. Same label, button, message and keyboard behaviour. Help (F10) should list it under H.

### F6 · P1 · Site-switch question: "stays in the top bar" is inaccurate, "Stay" is vague, and the toast covers the compass (shots 09, 1280-09)

**Problem.** After a switch, the incident shows in three places:
- the top-bar chip `INCIDENT · OTHER SITE`
- the status panel's first line, `Smoke reported at Fairmont Austin, floor 9 … not the site on screen`
- a map-edge chip, `Reported smoke at Fairmont Austin, floor 9 · not verified — show`. This is the way back.

The copy names only the chip, which cannot be clicked. `Stay` does not say where you stay, and a button read on its own by a screen reader must make sense. At 1280 the toast covers the compass and the `Viewing from S · looking N` caption.
**Spec.**
- Text: `Incident at Fairmont Austin. Switch to Long Center anyway?`
- Second line: `The report stays on screen: at the top of the status panel and as a map-edge chip to come back.`
- Buttons: [`Stay at Fairmont Austin`] (default focus) and [`Switch to Long Center`] (matches §12 `Switch to {site}`).
- Placement: when triggered from the Sites popover (S or the breadcrumb ▾), show the question inline in that popover, replacing the chosen site's row, with focus on Stay. Fall back to the toast only when triggered from a beacon or edge chip. Keep the toast clear of the compass column at 1280: offset it left, or move the compass up while the toast is shown.

### F7 · P2 · Unit option labels, mi vs miles, rounding (shots 01, 04, status bar)

**Problem.**
- The option labels mix spelled-out words and abbreviations: `Meters · km` / `Feet · miles` / `Yards · miles`. Values on screen are always abbreviated (`m`, `km`, `ft`, `mi`, `yd`).
- Feet switch to miles at 1,000 ft, so both rally points read `0.2 mi` (shot 01). Anything from about 950 to 1,300 ft gets the same label, and the operator can no longer compare primary with secondary.
- The status bar reads `Grid: 250 ft · bold lines 1250 ft`, with no thousands separator and "bold lines" as a noun phrase.

**Spec.**
- Options: `Meters and kilometers (m, km)` · `Feet and miles (ft, mi)` · `Yards and miles (yd, mi)`. Spell the words out once here and use the abbreviations everywhere else. Never write "miles" in a value.
- Feet show up to 1,500 ft in 50 ft steps (`1,050 ft`), then tenths of a mile. Yards show up to 1,000 yd. Metres are unchanged.
- Status bar: `Grid 250 ft · bold every 1,250 ft` · `Contours every 10 ft relative to hotel street level`. Use thousands separators in every formatter (`formatDistance`, `formatRadius`, `formatShort`, `groundLine`).

### F8 · P2 · Layers › Site: row label and the "Units in Display (D)" note (shots 03, 1280-03)

**Problem.**
- The row label `Elevation (terrain contours)` does not match help (`Elevation contours on / off`) or the status bar (`Elevation contours every…`).
- The note `Units in Display (D)` renders above the `Spacing` select (notes go before option rows in `renderLayers`), so it looks like a stray key line, and it is repeated under each layer that is on.
- It points away without saying what the current unit is.

**Spec.**
- Row label: `Elevation contours`.
- Order under an ON row: key swatches, then the option row (`Spacing [250 ft ▾]` / `Interval [10 ft ▾]`), then one muted line `Units: feet and miles · change in Display (D)`. Show that line once per Site group, under the last ground layer that is on, not once per layer.

### F9 · P2 · 3D labels after declutter: wording and identity tokens (shots 06, 07, 08)

**Problem.**
- The rally label reads `Rally point (secondary) · Draft · not approved`. The card and the §12 ruling use the `not approved` tag alone.
- The Layers key says `Draft · not approved`.
- Ruler brackets use dotted initials `A.K. ↓`, `M.R.`, but pins and rail badges use `AK`, `MR` (`twinHud.initialsBadge` strips the dots, and the ruler does not). The same person appears under two tokens side by side.
- The venue label `Texas Capitol · Day 3 10:00` drops the separator the card uses (`DAY 2 · 19:00`).
- Labels under panels are clipped: shot 07 shows `oup shelter · chaperones only` at the rail edge.
- Declutter can shift a label up to 64 px with no leader line back to its point.

**Spec.**
- 3D place labels: line 1 is the role, line 2 the name, and status is a suffix on line 1. Examples:
  - `Fire station` / `Austin Fire Station Number 1`
  - `Rally point (secondary) · not approved`
- Layers key: `Not approved (dashed)`.
- Initials have no periods anywhere: `AK ↓`.
- Venue label: `Texas Capitol · Day 3 · 10:00`.
- Declutter: treat the panel rectangles from `setSafeArea` as fixed obstacles, or hide labels whose anchor is under a panel. Draw a 1 px leader when a label shifts by more than one step (16 px).

### F10 · P2 · Help overlay: where things live, and grouping (twin.html `#tt-help`)

**Problem.**
- The 20 keys are in one flat list, which is past the 7±2 limit for a scannable list.
- `G` and `E` toggle layers but do not say where their options now live.
- `Frame the selection` does not frame a drawn path: F frames the person, and `Frame path` is a card button with no key.
- Go to floor is not mentioned.

**Spec.** Four groups with kickers:
- **VIEW:** `F / Z` Frame the selection (person, building or floor; a drawn path: *Frame path* on its card) · `, .` · `N` · `1 2 3`
- **FIND:** `A` · `[ ]` · `/` · `S` · `H` The site on screen, its Floors and *Go to floor* · `↑ ↓ Enter`
- **PANELS:** `L` Layers (what is drawn and its options) · `D` Display (units, motion) · `G` Scale grid on / off · spacing in Layers › Site · `E` Elevation contours on / off · interval in Layers › Site · `R` · `V`
- **EDIT AND EXIT:** `X` · `Esc` · `` ` `` · `?`

Keep the footer line `No key sends a message or dismisses a report.`

## Keep list

- **The Layers / Display rule** as worded. Spacing and interval under their layers, shown only when the layer is on (progressive disclosure that matches the rule).
- **Global units, one select.** The note names the surfaces it covers. Keep that sentence and extend it (F1, F3).
- **Per-unit memory of spacing and interval** (`spacing.ft`, `contour.ft`), so switching units back restores the operator's choice.
- **Framing in the panel-free area** (shot 02). The path sits between the rail and the card, with both ends labelled `Start · {name} (position at …)` and `End · {place}`. Keep `Frame path` on the card and F for the selection.
- **Go to floor above the stack**, the floor card it opens (`‹ Fairmont Austin`, `FLOOR · ESTIMATES`, breadcrumb `Fairmont Austin › Floor 9`), and clearing the field on success.
- **Showing the valid range in the miss message.** Keep `(1–37)`. Change only the sentence around it (F4).
- **Asking before leaving a live incident's site**, once and with default focus on staying. Keep `Switch to {site}` as the confirm verb (§12).
- **Declutter with the floor ruler fixed** as the obstacle: the ruler never moves and the initials slide around it (shot 08 reads cleanly).
- **Help footer** `No key sends a message or dismisses a report.`
- **Display's `Keyboard shortcuts (?)` footer link.** Help stays one click from the settings it explains.
