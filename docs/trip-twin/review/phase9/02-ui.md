# Phase 9: UI / visual review (select any path, path card, edit from the drawn line)

Review only. Shots: `review/phase9/shots/{1600,1280}-NN-*.png` and `*-text.json`. Code: `twinPaths.js` `drawPaths` (casing/glow), `page.js` `selectSuggestedPath` / `onMapIndex`, `twinHud.js` `resultEl`, `twinCustomPathsLayer.js` `drawSaved` / `drawEdit`, `tripTwin.css` (J3 `.tt-result`, J6 `.tt-path-pill`, J10 roles, `.tt-index-row`).

**Verdict:** The feature works. A drawn path opens a card, "Edit this path" seeds the editor (03 matches the line), and the card follows the J10 rule of one primary per region. The selection treatment breaks the colour contract, though. The white glow *replaces* the dark casing, so the selected path turns white and an alternate loses its dash (02, 06). Two smaller problems: the card shows the same result as the person card's J3 block but in different type, and the J6 path pill duplicates the card's actions and covers the editing banner (05). Fix 1 before the demo. Fix 2–6 in this phase.

## P0

### 1. The selected path turns white: the glow replaces the casing instead of surrounding it
**Shots:** 1600/1280-02 (main), 1600-06 (London alternate), 1600-04 (drive path at the right edge reads as a lit street).
**Problem:** When selected, the casing swaps `#061a23` for a 13–16 px `#eff7f3` glow at α.70. Inside it, the 6 px blue core has a soft glow edge, and the 3 px alternate dash is too thin to survive. In 02 the line reads white with a faint blue thread. In 06 the alternate is a solid white band with no dash, so the card says ALTERNATE while the map shows something heavier and more solid than the main. In 04 the selected drive path looks like a highlighted road. This breaks "blue only for paths". It also breaks the place rule this was meant to copy: a selected place (`twinSafety.js` `glowMat`) keeps its glyph colour and the glow sits *around* it.
**Spec (`twinPaths.js` `drawPaths`):** selection *adds* a layer and never recolours one.
- Glow (new, selected only): id `twin-path:${kind}:glow`, drawn under the casing at lift `primary ? 0.90 : 0.80`. Width core + 14 (main 20, alternate 17). `PolylineGlowMaterialProperty({ color: css('#eff7f3', 0.55), glowPower: 0.2 })`.
- Casing: always `#061a23` α.85, width core + 4 (main 10, alternate 7). It stays the dark separator between the white halo and the blue line.
- Core when selected: main width 7, `#3b82f6` α1. Alternate width 4, still `PolylineDashMaterialProperty` dashLength 18, add `gapColor: css('#061a23', 0.85)` so the dash still reads against the halo.
- Chevrons stay as they are.
- Test: in 06 the selected alternate must still read as a *dashed blue* line with a white halo, and in 02 the blue core must be the brightest stroke on the path.

## P1

### 2. Paths don't look clickable, and the alternate's target is 7 px
**Shots:** 1600-02/06 (the thin dashed alternate). Code: `tripTwin.js` MOUSE_MOVE only sets `grabbing` / `crosshair`.
**Problem:** The casing is the only hit target: 10 px for the main and 7 px for the alternate at any zoom. Nothing changes on hover: no cursor, no stroke change. The operator can't tell that the path is selectable, and the alternate is hard to hit.
**Spec:**
- Add a pick-only polyline per path, id `twin-path:${kind}:hit`, width 22 px, material `css('#061a23', 0.01)`, at the same positions as the casing. The existing `/^twin-path:(primary|alternate)/` regex already matches it.
- Hover: in the MOUSE_MOVE handler, when not dragging and there is no `pickHandler`, run `scene.pick` once per animation frame. If the id matches `twin-path:` (also `twin-saved:` / `twin-safety:`), set `cursor = 'pointer'` and lighten that path's casing to `rgba(42,74,89,0.95)` (the `--tt-hover-bg` base). Otherwise set the cursor back to `''`.
- No tooltip is needed. The card is the detail.

### 3. The J6 path pill duplicates the card and covers the editing banner
**Shots:** 1600/1280-04 (pill "Frame · Copy · Remove" above the card's "Frame path · Copy path summary"), 1600/1280-05 (in edit mode the pill still shows and the "EDITING PATH · click map: add waypoint…" banner seen in 03 is missing).
**Problem:** The same object has two action sets with different labels ("Frame" vs "Frame path", "Copy" vs "Copy path summary"), and only the pill can Remove. `.tt-path-pill` (z 13, top `--bar + g + 36px`) and `.tt-edit-banner` (z 12, top `--bar + g + 34px`) share one slot, so the pill hides the edit instructions.
**Spec:**
- `body.tt-editing .tt-path-pill { display: none; }`. The banner owns that slot while editing.
- While `selection.kind === 'suggested'` for the pill's drawn set, hide the pill (`pill.hidden = true`) and restore it when the card closes.
- Card gets the missing action. See #6 for the row layout.

### 4. The card restates the J3 result in different type
**Shots:** 1600-02/04/06 vs the person-card path section (phase 5 J3). Code: `selectSuggestedPath` builds `['lead', …]` lines from the same `routeCards()` output that `twinHud.js` `resultEl` renders as `.tt-result`.
**Problem:** The same path (04 starts from Emi Sato's card) shows as a mono 16 px metric with a blue rule in the person card, and as a 13 px sans `lead` line in the path card. Warnings are `.tt-edit-flag` here but `.w` there. The source is also said twice and differently. In 04 the notes say "Driving path from OpenStreetMap routing…" and the footer says "Planned from a card · OpenStreetMap routing". The editor (03/05) says "Suggested by Valhalla (FOSSGIS)". The start-position age the BACKLOG asks for is only on the map label ("59s old").
**Spec:**
- Export `resultEl(card, { kicker: false, route: false })` from `twinHud.js`. The card head already carries the kicker and the From → To. Pass the node into `card.place(info, [resultNode, acts])`. The `.flag` variant applies when `c.warnings.length`.
- Keep one footer line (`.tt-card-line.foot`): `{Rally path, planned automatically | Planned from a card} · OpenStreetMap routing (Valhalla · FOSSGIS) · start position {age}`. Add the age only when the start is a traveler. Drop "OpenStreetMap routing" from the notes. Use the same source string in the editor summary.
- Saved-path card, for consistency: render its distance/time as the same block with `.tt-result.saved { border-left-style: dashed; border-left-color: var(--tt-path-text); }`, mirroring the long dash on the map. Show day and mode as the `.r` line. Today the saved card's lead shows no time at all.

### 5. The kicker says "MAIN" and wraps; long titles run to 3 lines
**Shots:** 1280-02 ("SUGGESTED PATH · MAIN · / UNVERIFIED"), 1600-06 ("…ALTERNATE · / UNVERIFIED"), 1600/1280-04 (title on 3 lines).
**Problem:** "Main" appears nowhere else. The Layers legend, the "On the map now" rows, the breadcrumb ("› Suggested path") and the J3 kicker all say Suggested / Alternate. A wrapped mono kicker leaves "UNVERIFIED", the most important word, orphaned on line two.
**Spec:**
- Kicker: `SUGGESTED PATH · UNVERIFIED` / `ALTERNATE PATH · UNVERIFIED`. Fits in one line at 1280.
- `.tt-card-kind { white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }`.
- Path-card title: `.tt-card-name.clamp2 { display: -webkit-box; -webkit-line-clamp: 2; -webkit-box-orient: vertical; overflow: hidden; }`, with the full "From → To" in `title`.

### 6. The action row differs by path source, and the third button wraps alone
**Shots:** 1600/1280-04 ("Copy path summary" alone on row 2) vs 1600-02 / 06 (no copy at all).
**Problem:** Copy appears only when `set.source === 'route' && drawn`, so two cards of the same type have different actions, and when it does appear it wraps. Remove (#3) has no home on the card. The saved-path card has no primary, while the suggested card makes Edit primary, so the two path cards put their main action in different places.
**Spec:**
- Row 1 `.tt-actions`: `Edit this path` (`tt-btn primary`) and `Frame path` (`tt-btn`). Nothing else.
- Row 2 `.tt-actions` of `.tt-link`s, 8 px gap: `Copy path summary` on every suggested-path card (build the rally variant from `c` plus the set labels), and `Remove from map` for `source === 'route'` only. These are neutral links, not destructive, because nothing stored is deleted.
- Saved-path card: make `Edit saved path` the `primary` so both path cards share one anatomy.

## P2

### 7. Layers › "On the map now" rows rank below the empty saved-paths summary
**Shots:** 1600/1280-01 (rows read as legend notes; "▸ Saved paths 0 · avoid-areas 0" is heavier). The heading and first row sit above the captured scroll position, so this is judged from the visible row plus the code.
**Problem:** The rows are plain `tt-link` text with no underline, no swatch and no selected state. They keep the base `.tt-index-row` `margin-left: 22px`, so they don't line up with the summary. The heading is `.tt-key-note` (dim, α.85). Nothing tells the operator which path's card is open.
**Spec (`onMapIndex`):**
- Row: `[swatch] Suggested path → Rally point (primary)` with the meta right-aligned (`0.4 mi · 10–13 min`, `font: 500 11px var(--tt-mono)`, `--tt-text-dim`).
- Swatch: `.tt-swatch` in `--tt-path`, 3 px. Add `.dash` for the alternate, as in the legend above it.
- Text: `font: 500 12px var(--tt-font); color: var(--tt-text)`.
- `.tt-pop .tt-index-row { margin-left: 0; }`.
- Selected row (its card is open): `aria-current="true"`, `background: var(--tt-sel-bg); box-shadow: inset 2px 0 0 var(--tt-text)`. This is the list form of the white-glow rule.
- Heading `.tt-onmap-h`: `font: 500 11px/14px var(--tt-mono); letter-spacing: .12em; text-transform: uppercase; opacity: 1`.
- When both counts are 0, render "No saved paths or avoid-areas yet" as dim text, not a `<details>`.
