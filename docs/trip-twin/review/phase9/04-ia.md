# Phase 9 IA review: selecting a drawn suggested path

Reviewer: Information Architecture · 16 Oct 2026 · review only, no code edits.

Inputs: 06-layer-taxonomy.md (§3.7 PTH-02/03, §4.4 breadcrumb, §4.5 Esc, §10 path rows, §11 path verbs, §12 panel strings). 06 still ends at §13, so §14–§16 exist only in `review/phase6–8/04-ia.md`. Shots `1600-01…06`, `1280-02`, `1280-04`, `1600-text.json`. Code: `page.js` (`selectSuggestedPath` 2476–2551, `onMapIndex` 3238–3259, `savedIndex` 3260+, pick 624–629, Esc 4362), `tripTwin.js` (`drawnPaths` 1338–1349, `showRoute` replaces the rally set 1275–1282), `twinHud.js` 111–114 and 596, `twinPaths.js` 167–168, `twinPathEditor.js` 205, 296–297, 796, and `twin.html` (help 346–425).

Result: **1 P0 · 5 P1 · 3 P2**, plus §17 vocabulary rows.

Making the line clickable is the right move. It closes the gap noted in BACKLOG ("suggested paths … are not clickable"), and the card keeps the unverified caveat. The problems are these:
- The new verb says "edit", but the action makes a new path.
- The first path has four names across five surfaces.
- The index sits where operators do not look during an incident.
- The card breaks the breadcrumb and Esc hierarchy when it is opened from a person or place card.

## P1-A · P0 · "Edit this path" is not honest: it creates a NEW PATH and leaves the suggested path as it was

**Shots:** 02 → 03 (button `Edit this path`, then the editor kicker `NEW PATH · NOT SAVED`, the top-bar chip `EDITING PATH` and the banner `EDITING PATH · … Esc: discard`); 04 → 05 (the same, from a traveler); 06 (London alternate); help overlay `twin.html` 391–392.

**Problem.**
- 06 §11 names `Plan your own path` as "the one verb that opens the editor for a new path". It lists **"Edit this path" (for a new plan)** under Never say. Phase 9 ships exactly that string.
- "Edit" promises that the line on the map will change. It does not. The suggested path stays drawn, the result is a separate new path, and saving it creates a saved path next to the suggested one. An operator who "edits" the rally path in an incident will think the standing rally path now goes their way.
- Inside the editor, three labels disagree about what is happening. The kicker says `NEW PATH`, while the chip and banner say `EDITING PATH`. Saved-path editing uses `SAVED PATH · EDITING · saving clears its review` (`twinPathEditor.js` 296), so "editing" already means "changing a saved path".
- The verb also differs from the one on person and place cards. There, `Plan your own path` re-plans from the two ends (BACKLOG l.30). Here the editor is seeded with the line's turns. That is a real difference, and the label should say so.

**Spec.**
- Button: **`Plan your own path from this line`**. It keeps the §11 stem and names the seed. Do not use "Edit", "Modify", "Customize" or "Copy to editor".
- Editor kicker: `NEW PATH · FROM SUGGESTED PATH (MAIN) · NOT SAVED` (or `(ALTERNATE)`). The first editor line is `Started from the suggested path · that path stays on the map unchanged`.
- Top-bar chip and banner: `PLANNING PATH` for any new path, and `EDITING PATH` only when `edit.savedId` is set. Banner: `PLANNING PATH · click map: add waypoint · drag a number: move · click a number: remove · X: avoid-area · Esc: discard`.
- If the line's turns are **not** carried into the editor (shot 05 shows `WAYPOINTS · 0 OF 10` and 1.5 mi against 1.2 mi on the card), the label must be `Plan your own path (same ends)`. The label describes what the editor actually receives.

## P1-B · P1 · One path, four names: MAIN vs "primary" vs "Suggested path" across card, Layers, breadcrumb and incident panel

**Shots:** 01, 02, 06 and code.

| Surface | First path | Second path |
|---|---|---|
| Card kicker (page.js 2533) | `SUGGESTED PATH · MAIN · UNVERIFIED` | `… · ALTERNATE · …` |
| Layers › Paths row (3251) | `Suggested path · Rally point (primary) · 0.4 mi` | `Alternate path · …` |
| Layers legend key (2983) | `Suggested path` | `Alternate` |
| Breadcrumb (2550) | `› Suggested path` | `› Alternate path` |
| Incident panel card (twinHud 114) | `Path to rally point (primary)` | `Alternate path` |
| Incident summary line (twinHud 596) | `If the group must move: rally point (primary)` | — |
| Copied text (twinPaths 168) | `Rally point (primary) · …` | `Alternate path · …` |
| 06 PTH-02 | `Primary` | `Alternate` |

**Problem.**
- 06 §11 defines "Suggested path" as the **type**: every router path, the alternate included. Layers, the legend and the breadcrumb also use it as the **rank** of the first path. Read that way, the alternate is not "suggested", or the first path is the endorsed one.
- PTH-02 calls the first path "Primary". The build swapped in MAIN, correctly, because "primary" already ranks rally points (`Rally point (primary)`, §12). The result would be "Primary path to Rally point (primary)". But 06 was never amended, and the incident panel still says "Path to rally point (primary)", so the operator cannot tell whether "primary" describes the path or the point.
- Case drifts too: `rally point (primary)` appears in twinHud 114/596, while §12 requires the same string as the rail, `Rally point (primary)`.

**Spec.** Rank words are **Main / Alternate**, for paths only. **primary / secondary** are for rally points only. "Suggested path" is the type and never a rank.
- Amend PTH-02: `Main / Alternate`. Main is the router's first result. It is not a recommendation. Never say: primary (for a path), best, recommended, preferred, backup.
- Card kicker: keep `SUGGESTED PATH · MAIN · UNVERIFIED` / `· ALTERNATE ·`. Drop the rank when the set has only one drawn path (shot 04, a single drive): `SUGGESTED PATH · UNVERIFIED`.
- Layers row: `Main · {From} → {To} · {walk|drive} {d}` / `Alternate · …` (see P1-D).
- Legend keys: `Main` (solid glow) · `Alternate` (dash), under the `Suggested paths` toggle.
- Breadcrumb: `› Suggested path · main` / `› Suggested path · alternate`.
- Incident panel titles: `Main path to Rally point (primary)` / `Alternate path to Rally point (primary)`. Summary line: `If the group must move: main path to Rally point (primary) · details below`.
- Copied text: `Main path · Rally point (primary) · {d} · walk {a}–{b} min (group pace)`.

## P1-C · P1 · Breadcrumb: the focus segment truncates, and a path opened from a card loses its parent

**Shots:** 02 and 04 at 1600 (`World View › Spring choir tour (s... › Fairmont Austin ▾ › Suggested...`); 03 and 05 at 1600 (`› Ne...` for "New path (not saved)"); 1280-02 and 1280-04 (`Fairmont Austin › Suggested path`: the parent segments drop instead).

**Problem.**
- 06 §4.4 says: "The focus segment never truncates", and the trip title truncates first. At 1600 the focus is the segment that gets cut. At 1280 the behaviour is the opposite, and it is closer to the spec.
- In shot 04 the path came from Emi Sato's card. The breadcrumb jumps from `› Emi Sato` straight to `› Suggested path`, so the person level disappears. Esc on the path card clears the selection and hides the card (page.js 4362–4365). It does not go back to Emi's card. 06 §4.5 requires Esc to unwind **one** level.

**Spec.**
- Truncation order at every width: trip title (to 24 characters plus …, with a full-text tooltip), then `World View` is replaced by `…`, then the hotel name. The focus segment is never cut. If it does not fit, the focus segment wraps the breadcrumb to a second line.
- A path opened from a card is a child of that card:
  - From a person: `{site} › {Emi S.} › Suggested path` (the person segment is a link and reopens the person card).
  - From a place: `{site} › {Dell Seton Medical Center} › Suggested path`. Use the place's short name, ≤ 28 characters, as in phase 8 M3.
  - Rally path (no parent card): `{site} › Suggested path · main`.
- Esc on a path card that came from a card: close the path card, reopen the parent card and keep the path drawn. The next Esc follows the existing chain. Focus returns to the row or pin that opened it (§4.6).

## P1-D · P1 · Where the index lives: "On the map now" is hidden in a legend panel, mislabelled, and missing origin and mode

**Shots:** 01 (Layers › Paths: the toggles and legend, then `On the map now` styled as a note, the two rows, then `▸ Saved paths 0 · avoid-areas 0`); 04 (a card route replaces the rally set, `tripTwin.js` 1281); 02 (incident and rail surfaces do not link to the path).

**Problem.**
- **Heading:** saved paths are on the map now too, yet they are listed under a different heading below. "On the map now" really means "suggested paths drawn now". It is rendered as `tt-key-note` (a caption), not as a sub-kicker, so it reads as a note on the Avoid-areas legend above it.
- **Rows:** `{type} path · {toLabel} · {d}` has no origin and no mode. For the shot 04 route, the row would read `Suggested path · Ascension Dell Seton Medical Center at The University of Texas · 1.2 mi`. "From Emi Sato" and "drive" are missing, and the destination alone does not tell the operator which line it is.
- **"Saved paths" appears twice** in the same group: once as a toggle, once as the index summary `Saved paths 0 · avoid-areas 0`. The summary also mixes two kinds of object.
- **Placement:** in an incident the operator reads the incident panel ("If the group must move", path cards with the caveat), not Layers. Those cards, and the path banner in shot 04, do not open the path card. Only the 3D line and a row three levels deep in Layers do. That is not reachable for keyboard users in the sense of §4.6 ("every drawn item is also reachable as a list row") unless they know to open L and scroll.

**Spec.** Layers › Paths:
```
PATHS
  [x] Suggested paths     ── Main   - - Alternate   ▒ Within {0.62 mi} of a heat detection
  [x] Saved paths         ─ ─ Saved path (long dash) · Advance shows the selected day
  [x] Avoid-areas         ◯ Avoid-area · applies to every path on this trip
  SUGGESTED · DRAWN NOW · 2                       ← sub-kicker, same style as "Weather overlays"
    Main · Fairmont Austin → Rally point (primary) · walk 0.4 mi
    Alternate · Fairmont Austin → Rally point (primary) · walk 0.4 mi
  ▸ SAVED ON THIS TRIP · 0                         ← details; rows by day as today
  ▸ AVOID-AREAS · 0                                ← separate details
```
- Empty state, instead of a missing heading: `No suggested path drawn · open a person, place or site card to find one`.
- Card route row: `Main · Emi S. → Dell Seton Medical Center · drive 1.2 mi`. Use the short name and first name + initial (as copied text does, §12).
- Second entry point, where people actually look: the incident-panel path titles (`Main path to Rally point (primary) ›`) and the path banner title become buttons that open the same card. No new rail section: the rail stays about people.

## P1-E · P1 · The action set differs for every path, and the banner repeats it under other names

**Shots:** 02 and 06 (rally: `Edit this path · Frame path`); 04 (card route: `Edit this path · Frame path · Copy path summary`, and the banner above at the same time: `Frame · Copy · Remove`).

**Problem.**
- The same verbs appear under two names on one screen: `Frame` / `Frame path`, `Copy` / `Copy path summary`. §12 fixes `Copy path summary` and `Remove path`. The abbreviations break the "names are contracts" rule.
- `Remove path` exists only on the banner, abbreviated, and the card has no remove action.
- The rally path, the one most likely to be read to chaperones in an incident, has **no** `Copy path summary`. The condition `set.source === 'route'` (2523) excludes it.

**Spec.**
- One ordered action set on every suggested-path card: `Frame path · Copy path summary · Plan your own path from this line · Remove path`.
- `Remove path` appears only for card routes. On the rally path, put a foot line in its place: `Shown while a primary rally point is set · hide in Layers › Paths › Suggested paths`.
- Copy for the rally path uses the P1-B copied-text format.
- While a path card is open, the banner keeps only its title (a button that opens the card, per P1-D). Its own buttons hide, so each verb appears once on screen. When no card is open, the banner uses the full §12 labels.

## P1-F · P1 · Planning from a traveler's path: two start names, two distances, and a Save button that cannot save

**Shots:** 04 → 05.

**Problem.**
- One point carries two map labels: `Start · Emi Sato (position at 21:31 · 59s old)` and `Start · a traveler's position`.
- Two distances are on screen for "the same" path. The banner still shows `Drive 1.2 mi`, while the editor shows `1.5 mi · drive 3–5 min`, and nothing says which line is which.
- The Name field is prefilled `a traveler's position → Ascension Dell Seton`, in lower case, for a path that can never be saved. `Save path` is drawn as a dashed button, and the reason it cannot be used sits two blocks below it.
- The card names `Emi Sato` and the editor hides the name. Phase 4 H4 forbids **storing** a traveler's name or position. It does not forbid showing it while the path is live.

**Spec.**
- Kicker: `NEW PATH · LIVE ONLY · CANNOT BE SAVED`. Hide `Name`, `Day`, `For event` and `Save path` (nothing is kept). The actions are `Frame path · Copy path summary · Discard`. The note reads `Starts at Emi S.'s position (21:31, 59 s old) · shown live only · to save, plan from a site or a place`.
- One start label: `Start · Emi S. · position at 21:31 (59 s old)` (PTH-10 pattern).
- While the editor is open, hide the original drawn route and its banner, or label it `Suggested path (before your changes) · drive 1.2 mi`. There should never be two unlabelled distances.

## P1-G · P2 · A saved path started from a suggested one takes the same name, and its waypoints repeat a street name

**Shot:** 03 (Name `Fairmont Austin → Rally point (primary)`, the same as the suggested card title; waypoints `1 · Waller Creek Greenbelt Trail`, `2 · Waller Creek Greenbelt Trail`).

**Problem.**
- After saving, Layers lists `Main · Fairmont Austin → Rally point (primary)` and a saved `Fairmont Austin → Rally point (primary) · walk · not reviewed`. Two objects share one name. One can be reviewed and the other cannot.
- Waypoint labels that repeat one street give no way to tell the rows apart when reordering.

**Spec.**
- Default name: `{From} → {To} · via {street of the first waypoint that differs from the suggested line}`. If there is none: `· planned {HH:MM}`.
- The saved card adds a provenance line: `Started from the suggested path (main) · {day time zone}`.
- Waypoint rows: `{n} · {street} · {d} from start`, e.g. `1 · Waller Creek Greenbelt Trail · 0.1 mi from start`.

## P1-H · P2 · Card copy drifts from 06: mode missing, caveat shortened, two router names

**Shots:** 02, 04, 06 and the editor in 03 and 05.

**Problem and spec.**
- **Mode.** The title `{From} → {To}` replaces §10 `Walk from <origin> to <place>`, but nothing on the card says walk or drive in the first two lines (04 is a drive). Lead the metric with the mode: `Walk · 0.4 mi · 10–13 min · group pace` / `Drive · 1.2 mi · 3–5 min · no live traffic`. Amend the §10 row to `{From} → {To}`, with the mode in the metric line.
- **Caveat.** `not checked for closures, crowds or lighting` drops "crime or damage". PTH-03 forbids shortened forms. Use the full PTH-03 string, or amend PTH-03 once and use it everywhere (the card, twinHud 122, the editor).
- **Source.** The card says `OpenStreetMap routing`, and the editor says `Suggested by Valhalla (FOSSGIS)` for the same line. Use one string: `Suggested by OpenStreetMap routing (Valhalla · FOSSGIS) · unverified`. Remove the separate `Suggested · unverified` prefix, because the kicker already says UNVERIFIED.
- **Destination string.** `Planned automatically to the primary rally point` becomes `Planned automatically to Rally point (primary)` (§12: same string as the rail). Add the rally point's place name to the title when one is on file: `Fairmont Austin → Rally point (primary) · {Republic Square}`.
- At 1280 the kicker wraps to two lines (1280-02, 04). Once the rank is dropped for single paths, the longest kicker is `SUGGESTED PATH · ALTERNATE · UNVERIFIED`. Allow it to wrap after `PATH ·`, never inside a word group.

## P1-I · P2 · Help overlay: the path row exists but uses the retired verb and gives no keyboard route

**Code:** `twin.html` 391–392 (`Click a path` → `Its details; Edit this path opens the editor on that line`, under "Find" in a sheet titled KEYBOARD); 417–421 (Esc).

**Problem.** The overlay does mention path selection, contrary to the brief, but the row is mouse-only and repeats "Edit this path". Esc still reads "Close panel, then the path, …" and does not mention the path card or going back to its parent.

**Spec.**
- Find row: `Click a path, or Layers (L) › Paths › Suggested · drawn now` → `Its card: Frame path · Copy path summary · Plan your own path from this line`. Do not add a new key. The Layers index is the keyboard route (§4.6).
- Esc row (with phase 7 L9 / phase 8 M10 still pending): `Close panel, then weather back to now, then end Ways out, then the path card (back to the card it came from), then the path, then step back (place or person › floor card › site), then clear the selection (never exits)`.
