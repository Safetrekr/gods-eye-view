# Phase 9 UX review: select any path, see its details, edit it

Jesse's ask: "select each unique route and view the details, and from there manually edit them."
Short verdict: you can select a path, and the white glow plus the card make the selection clear. Three things fall short. It is hard to tell that a path can be clicked. The card gives a summary, not details. "Edit this path" can quietly turn into a different path.

Works well: the white glow on the selected path (02, 06). Main and alternate can each be selected on their own (06). The card is honest that the path is unverified. Waypoints are seeded from the path's turning points (03), and in the walk case the re-planned line is very close to the original (0.4 mi, 10–13 min in both). Keyboard users can reach every path through Layers. Esc deselects the path before it removes it.

Shots: `shots/1600-NN`. Code: `gods-eye-view/src/operations/tripTwin/`.

---

## P0

### 1. "Edit this path" re-plans with a different router, so the edited line can differ from the one you clicked, and nothing says so
- **Shot:** 04 → 05. The card says **1.2 mi · 3–5 min**. The editor opened from that card says **1.5 mi** with **WAYPOINTS · 0 OF 10**. Card source: "OpenStreetMap routing". Editor source: "Suggested by Valhalla (FOSSGIS)".
- **Problem:** Suggested paths come from OSRM (`twinPaths.js:2`, `twinRoutes.js`). The editor sends the seeded points to Valhalla (`twinCustomPaths.js:106`). Seeding is the only thing holding the shape. For the drive path, `seedWaypoints` returned no points: every turn was within `minGapM` (up to 150 m) of an end or neighbour, or within the 20 m tolerance. With no waypoints, Valhalla planned its own path. The original glow is cleared and no copy of the original stays on screen, so the operator cannot see that the line changed. They would save a path they never looked at, believing it was the one they reviewed. On a safety product, that breaks the promise "edit the same line".
- **Fix:**
  1. When the editor opens, show the original geometry as the result. Keep `result = original`, label it "From the suggested path (OSRM, 21:31)", and do not re-plan until the operator changes something (adds, moves or removes a waypoint, switches mode, adds an avoid-area). If they save with no changes, the saved path is exactly what they clicked.
  2. Throughout editing, keep the original on the map as a ghost: a 40%-white dashed line labeled "Original suggestion".
  3. After the first re-plan, compare the new line with the original (largest deviation and distance change). If it moved more than about 25 m or the distance changed by more than 5%, show a notice at the top of the editor: "Re-planned by Valhalla: 1.5 mi (was 1.2 mi). The original is shown dashed." Add one button, "Match original": add seed points where the deviation is largest, up to the 10-waypoint cap, and plan again.
  4. Never seed zero waypoints for a path longer than 500 m. Always add at least the point at half the path's length.
  5. Name the engine in the card's source line: "OSRM (OpenStreetMap data)". Then card and editor read as two engines, not one engine with two names.

## P1

### 2. Nothing on the map shows that a path can be clicked
- **Shot:** 01, 02. The path is a thin blue line with chevrons and nothing changes when you hover it.
- **Problem:** No hover handling exists. The only cursor changes are `grabbing` and `crosshair` (`tripTwin.js:608/619/1439`). The click target is the dark casing: 10 px wide for the main path and **7 px** for the alternate (`twinPaths.js:223`). Chevrons have no id, so a click on one does nothing. Buildings in front of the path (02, the tall tower) block clicks on those stretches. Jesse "assumed" he could click a path, and nothing on screen confirms it. The 7 px target is below the 24 px minimum in WCAG 2.5.8. It passes only under the exception for an equivalent control (the Layers list), and that list is hard to find (finding 3).
- **Fix:**
  - Throttle a MOUSE_MOVE pick to about 60 ms. When the pointer is over `twin-path:*`, set the cursor to `pointer`, brighten the casing (the white glow at half strength), and show a tooltip: "Suggested path · 0.4 mi · click for details".
  - Add an invisible pick polyline per path, 24 px wide with alpha 0.01, so near misses still hit.
  - Give chevrons the path's id prefix.
  - The first time paths are drawn, add a hint to the route banner: "Click a path for details and editing."

### 3. "On the map now" is hidden in the middle of the Layers legend and its rows read like legend text
- **Shot:** 01 (at both widths). The rows sit under the PATHS legend, above SITE. The first row is cut off at the top of the scroll. They look the same as the legend captions. Both rows end in "Rally point (primary) · 0.4 mi", and neither says where the path starts.
- **Problem:** People expect a list of things they can select, not a panel of layer switches (Jakob's law). Nothing marks the rows as buttons: no chevron, no hover style, no `aria-current` on the selected row. When a path is opened from the list (or from a traveler card, 04), the camera stays where it was. In 04 the path is mostly off screen while its card is open.
- **Fix:**
  - Move "Paths on the map" to the top of the PATHS group, above the legend.
  - Row format: "Main · Fairmont Austin → Rally point (primary) · 0.4 mi · walk ›".
  - Hover and focus style matching `.tt-index-row` on saved paths, plus a trailing chevron.
  - `aria-current="true"` on the selected row.
  - When a path is opened from the list or a card, call `frameGeometry` on it. Map clicks keep the current camera.
  - Add a **Details** button to the route banner (04: "Path: Emi Sato → … Frame · Copy · Remove") that opens the same card.

### 4. The card is a summary, not "details"
- **Shot:** 02, 04, 06. Each card shows distance and time, an unverified notice, and a one-line source.
- **Problem:** The backlog asked for checks and flags, source and run, and the age of the start position. Missing:
  - Which streets the path follows.
  - When it was planned.
  - The start position's age. It appears on the map label ("59s old", 04) but is stripped from the card name by `replace(/ \(.*\)$/,'')` at `page.js:2549`.
  - The checks the editor already runs ("No checks raised").
  - How the main and alternate differ.

  To answer "is this a good path?", the operator has to open the editor.
- **Fix:** Add these rows in this order:
  - `Via Waller Creek Greenbelt Trail, E Cesar Chavez St` (street names along the turning points, reusing `placeName`).
  - `Start: Emi Sato's position at 21:31 · 59 s old` (card paths only).
  - `Checks: none raised`, or the flag list, using the same `checksFor` used for saved paths. Prefix it "not a verification".
  - `Planned 21:31 · OSRM (OpenStreetMap data)`.
  - Main and alternate only: `Alternate · 590 m (+120 m) · Show alternate ›`, and the reverse on the alternate's card.

### 5. The editor doesn't say it is editing this path, and saving leaves two lines on the map
- **Shot:** 03. The header says "NEW PATH · NOT SAVED" and the breadcrumb says "› New path". The glow is gone.
- **Problem:** The editor has no idea where its path came from (`pathEditor.start` gets no origin). It looks like a separate tool, not the editing step Jesse asked for. Discard closes everything; it does not return to the path card. After Save, the automatic suggestion is still drawn alongside the saved long-dash path, so the operator sees two nearly identical lines and can't tell which one chaperones should follow.
- **Fix:**
  - Pass `origin: {kind:'suggested', pathKind, source, plannedAt}` to the editor.
  - Header: "EDITING A COPY · SUGGESTED PATH (MAIN)". Breadcrumb: "› Suggested path › Editing copy".
  - Discard returns to the path card with the glow back on.
  - After Save, open the saved-path card with the line "Based on the suggested path (OSRM, 21:31)". While a saved path exists for the same start and end, fade the automatic suggestion to 40% and add "Show automatic suggestion" to Layers.

### 6. You only learn a path is live-only after you are in the editor, and the reason sits below the buttons
- **Shot:** 04 → 05. The card's main button is "Edit this path" with no warning. In the editor, Save is dashed (disabled) and the reason appears *below* Save and Discard.
- **Problem:** The operator does all the edit work and only then finds out it can't be kept. The privacy rule is right; the order in which it is explained is not.
- **Fix:**
  - On the card, label the button "Edit (live only)" and add the line "Starts at a traveler's position: edits can't be saved." Add a secondary action, "Plan from Fairmont Austin instead", which opens a saveable editor from the site to the same destination.
  - In the editor, move the live-only notice to the top of the panel above Name, styled as a notice block.
  - Give Save `aria-disabled="true"` with `aria-describedby` pointing at that notice.

## P2

### 7. Two "Start" labels overlap, and the traveler is named on one and anonymous on the other
- **Shot:** 05. "Start · Emi Sato (position at 21:31 · 59s old)" sits directly above "Start · a traveler's position". The card title says "Emi Sato"; the editor name says "a traveler's position".
- **Fix:** While editing, hide the original route's end labels; the ghost line from finding 1 carries no labels. Use one start label everywhere: "Start · Emi Sato's position (59 s old · live only)". Showing the name is fine, because the rule is about storing it, and the name is still never written to the stored path.

### 8. Seeded waypoints can't be told apart and don't say they were placed automatically
- **Shot:** 03. The rows read "1 · Waller Creek Greenbelt Trail" and "2 · Waller Creek Greenbelt Trail".
- **Problem:** The operator can't tell which marker is which, or that these points only hold the suggested shape and can be removed freely.
- **Fix:** Kicker: "WAYPOINTS · 2 OF 10 · placed at the suggested path's turns". Row: "1 · Waller Creek Greenbelt Trail · 120 m from start". When two names match, add the nearest cross street. Hovering a row highlights its numbered marker.

### 9. Editing the standing rally path saves it for one day only
- **Shot:** 03. The Day field is set to "Day 1" (`page.js:2514`, `todayDay()`).
- **Problem:** The rally path applies on every day. Saved as Day 1, it disappears in Advance on Day 2 and Day 3, and nothing says why.
- **Fix:** When editing a rally or hotel path (`set.source === 'rally'`), seed `day: null` ("Any day"). Card paths keep today's day.

### 10. Actions are split between the banner and the card, and Copy is missing on standing paths
- **Shot:** 04 has Frame and Copy in both the top banner and the card. 02 and 06 have no "Copy path summary" (`page.js:2522`, card paths only).
- **Fix:** The card holds all actions. The banner keeps a one-line summary plus **Details** and **Remove**. Add "Copy path summary" for rally and alternate paths too, using the same text with the line "Planned automatically to the primary rally point".
